# 可配置原媒体下载大小

用户确认：不再把单文件 128 MB 写死。最大下载大小由用户在页面主动设置，并与模型上传限制分开。

## 设置与当前值

- 入口：设置 → 处理设置 → 原始媒体 → 单个文件最大下载大小（MB）。
- 默认及本机当前值：1024 MB；可设置整数 1–2048 MB，单位为十进制 MB。
- 配置字段：库内 `settings.max_download_mb`；管理接口 `preferences` 读取、`preferences-save` 保存。
- 老库未设置时使用 1024 MB；老客户端只保存媒体开关时不重置已选大小。
- 用于后续下载；降低后不会删除原文件，已保存文件仍可处理。已运行的下载沿用启动时读取的配置。
- 2048 MB 是当前本地原媒体读写支持范围，在页面明确显示；不是无限文件支持。

## 实现范围

- 单条链接和来源同步都由统一下载器接收库设置。
- 超出设置值时停止，不把截断文件标为下载成功。大小已知先检查声明值；大小未知按实际字节累计检查。
- 大传输超过 8 MB 后流式写临时盘，结束后读取并登记，失败自动清理临时文件。后续媒体处理仍使用既有受控文件和 bytes 接口，不宣称整条链路零内存读取。
- 原媒体登记、读取、LocalMedia 准备、CLI 本地媒体读取和资料管理清单已解除旧 128 MB 限制。
- 单作品原媒体总量最多 2048 MB；转写音频/关键帧批次仍保留独立 512 MB 预算。原视频不再扣减关键帧预算。
- 模型上传单输入 32 MB 等约束不变；原视频经音频分段与选帧后发送，不直接将大原视频上传给模型。
- 同步结果提示改为引导调整处理设置，不再把旧记录解释成“当前固定128MB”。
- 备份/导出仍有自己的包大小限制，不等同于单文件下载限制。

## 验证

- 合成 129 MB 原视频：真实落盘、登记、准备清单、读取成功；解码使用隔离测试解码器，未将它冒称为真实平台视频完整转写验收。
- 验证设置保存/重新读取、旧客户端保留设置、非法值拒绝且不改库、下载器使用配置、降低限额不影响已存内容、模型上传限制不变。
- 验证大下载临时缓冲滚到磁盘并清理，原视频不占用音频/关键帧预算。
- 相关后端回归 171 项通过、2 项跳过；额外输入登记/媒体/备份/管理接口回归 71 项通过（包含交集，不能相加）。前端 166 项通过。
- 已在本机保存 1024 MB 并载入新版后台，不触发真实批量同步或云模型调用。
- 全量后端回归另有 3848 项通过、7 项失败、10 项跳过；失败集中于旧页面文件/CSS、旧认证启动和旧 Linux 暂存清单的断言。空配置启动测试曾长时间运行并收到中断信号，本次全量记录不能作为全量发布通过的凭证。此批不扩展修改旧启动/打包流程，下载设置专项仍独立验收。
