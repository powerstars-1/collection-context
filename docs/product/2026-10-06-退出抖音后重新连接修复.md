# 退出抖音后重新连接修复

## 根因与修改

`launcher.launch(no_browser=True)` 原先把“不自动打开管理页面”直接传给 `launcher_resources(headless=...)`，因此 Mac 常驻启动也把抖音登录浏览器变成无界面模式。退出真实登录后，前端依据 `headless=true` 禁用重新登录入口。

已拆分两个选项：

- `--no-browser` 只影响管理页是否自动打开。
- 抖音连接默认依据桌面可用性选择模式：Mac/Windows 桌面可以打开登录窗口；无桌面 Linux 保持无界面。
- 新增独立的 `--source-connect-headless` / `launch(source_connect_headless=...)` 供明确无界面部署使用，不与管理页选项捆绑。
- 退出登录仍只用无界面浏览器清除本产品登录；之后重新登录使用桌面可见浏览器。同步 worker 的无界面运行不改变。

## 验证与状态

- 新增 6 组桌面/管理页开关/显式无界面组合测试。
- 新增合成“已连接 → 退出 → 再登录”完整回路，验证退出清除登录、再登录选择可见浏览器、既有资料不变、没有同步或模型任务。
- 启动、连接、资源和本机页面相关测试 140 项通过。
- 本机 8790 已重新载入。真实 API 返回 `enabled=true, headless=false`；真实页面按钮 `isEnabled=true`。
- 实际点击“连接抖音”，后台进入 `mode=login, state=running` 并记录 `browser_ready_at`，没有错误；可见浏览器启动成功。
- 用户尚未完成此次登录时，不标记真实账号重新连接已完成；扫码及验证由用户操作。未自动同步、未调用云模型。
