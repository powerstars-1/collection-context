# 统一后端：自动边界与历史批次验证

日期：2026-10-01。状态：自有持久策略与安装进程验证通过；完整来源、管理页和三端仍在实施。

## 1. 本次实际实现

`workflows/policy.py` 定义执行门禁，`workflows/scheduling.py` 承载自动规则、历史批次和选定积压恢复。沿用统一文件提交、模型/输入登记和后台执行器，不引入另一套任务框架、第三方客户端或数据库。此处的自动提取与定时平台同步是两个不同开关，本次没有改变自动同步。

| 模式 | 哪些资料会进入 | 费用/暂停边界 |
| --- | --- | --- |
| 手动 | 用户明确指定已准备输入，原有 `submit-extraction` | 每任务固定调用上限；不受自动开关影响 |
| 新资料自动 | 本地拥有者在启用之后首次发现、已登记媒体、未排除且从未提交过处理的作品 | 固定本次模型/输入/预算；本次总新任务上限默认5，达到后不无限重置 |
| 历史批次 | 用户明确选择1至20个输入 | 先全部校验，再原子排队；每条/整批调用上限明确，可取消整批 |
| 暂停积压恢复 | 用户从已暂停自动任务中明确选择最多20条 | 先展示数量/额度和预览标识，确认后才恢复；沿用原任务固定模型 |

### 自动观察边界

- 以库提交代际为启用边界；首次发现代际与发现主体由本系统保存，不从平台正文采纳这些字段，不依赖时间戳恰好不同。
- 未知点赞/收藏时间继续为未知；“新发现”不表示“刚点赞”。早期库没有首次发现代际/主体的资料按历史处理。
- 同一作品新增来源关系不产生新首次发现；已有处理任务的作品不会因为原文/媒体更新被自动重试。确需重新处理，走显式手动/历史操作。
- 低权限主体发现的条目不会继承本地拥有者的自动模型权限。当前公共AI接口仍只读，没有因此开放添加/计费端点；未来接入必须传递经过认证的发现主体。
- 新内容未取得媒体时仅保留资料，不伪造输入或发模型请求。准备失败记录可见问题，后续空闲轮询不重复创建失败任务或库提交。

### 开关与积压

关闭自动提取立即拒绝新自动登记，并暂停未开始的自动任务。已开始的当前提取允许结束，后续自动任务不启动；要停止当前任务，另用 `cancel-job`，已发出的请求仍可能收费。

重新启用生成新的规则/观察边界：不会处理旧资料、暂停期间资料、已达到上限而未登记的旧候选或旧自动积压。旧积压需明确选择、预览、确认；其他旧资料走手动/历史。预览后开关、任务状态/计划或调用记录变化会让预览失效。

本次授权的新任务总上限不是每轮重置，也不是金额上限。每条调用上限与新任务总数的乘积给出最多预占请求数；实际收费与用量仍以供应商为准。本次上限默认5，可显式配置1至1000；超限需要新授权，不暗中转为无限历史处理。

## 2. 开发候选操作

先在新产品独立工作目录登记音频、视觉、文本三个角色；角色可以指向用户配置的同一兼容接口，但输入能力需分别验收。以下额度只作命令示例，不代表所有视频能用3次请求完整处理。

```bash
collection-context --workspace "<独立工作目录>" processing-settings
collection-context --workspace "<独立工作目录>" configure-auto \
  --enabled yes --max-calls 3 --max-new-tasks 5 --allow-model-calls
collection-context --workspace "<独立工作目录>" worker \
  --credential-dir "<库外独立凭据目录>" --allow-model-calls
```

配置只保存规则，不解析模型密钥或发模型请求。后台启动同样须显式确认；只读页面/查询不会启动它。`processing-settings` 返回启用状态、边界、本次上限/已登记/剩余数、暂停任务ID和准备问题；未配置规则时初始化关闭。

```bash
collection-context --workspace "<独立工作目录>" configure-auto --enabled no

collection-context --workspace "<独立工作目录>" resume-auto --job-id "<暂停任务ID>"
collection-context --workspace "<独立工作目录>" resume-auto \
  --job-id "<同一暂停任务ID>" --preview-token "<刚返回的标识>" --allow-model-calls
```

恢复积压前需先启用新的自动规则，再预览选中旧任务；重新启用本身不恢复它们。多个 `--job-id` 可组合，不能用“全部”模糊授权无限队列。

```bash
collection-context --workspace "<独立工作目录>" submit-history \
  --input-id "<已登记输入1>" --input-id "<已登记输入2>" \
  --idempotency-key "<此批次稳定唯一键>" --max-calls 3 --allow-model-calls
collection-context --workspace "<独立工作目录>" cancel-history --batch-id "<返回的批次ID>"
```

本例两条每条最多3次，整批最多6次。相同幂等键同参数返回原批次；资料、配置、顺序或额度不一致返回冲突，不重建第二批。任何输入无效或提交失败都不部分排队。取消保留已完成结果与晚到用量，不承诺供应商撤销请求/退款。

## 3. 防止旧包绕过新规则

写协议升为 `os_writer_v2`，不改变资料schema1或内容引用。v1旧执行器不认识调度权限；v2写保护使它在启动任务/记录请求意图的事务中被拒绝，不能靠忽略暂停规则派发模型。

已有v1开发库可只读；写入需要**显式** `upgrade-writer`。升级同时获取内核执行/写锁，正在执行任务时拒绝；只接受已知v1永久保护标记，不根据文件年龄/PID清锁、不降级未知版本。先写新保护再写配置，配置失败可续接已知升级标记，原资料提交不变。

```bash
collection-context --workspace "<已核实的早期开发目录>" upgrade-writer
```

本次只升级用旧候选实际创建的一份原创测试库；用户生产/真实样例库均未升级。回退旧代码不能写v2库，须保留只读与完整任务记录，不删除未知请求记录以重发。
