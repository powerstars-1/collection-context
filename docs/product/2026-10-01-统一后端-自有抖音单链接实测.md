# 自有抖音连接：单链接实际验证

状态：开发切片。完整 MVP 仍在实施；本记录不代表五来源、三平台或转写质量已验收。

## 自主重写的边界

新模块 `backend/src/collection_context/sources/` 自行识别链接、观察正常网页返回、解析作品身份/描述/媒体页序，并通过统一库入库。没有导入旧 `app`、dYm、All-IN-ONE、其他项目的签名库/CLI或账号目录。通用 Playwright 仅负责独立浏览器，网络观察依据其[官方说明](https://playwright.dev/python/docs/network)；平台网页响应是本次实际观察，不是抖音承诺稳定的公开 API。

浏览器只监听指定作品的正常详情响应，不伪造签名，不调用私有登录配置，不绕过验证码/登录/作品权限。不读取其他推荐作品作为目标资料。原媒体使用页面返回的临时地址；签名不进入公开素材正文、库提交或报告。

浏览器目录必须在资料库外。首次使用新空目录写入本产品身份标记；后续验证身份和私有权限。非空的第三方浏览器目录拒绝使用，也不会为了接入而修改其权限。桌面登录入口和私人来源验证下一步实施；本轮没有用户登录。

## 已接线的本地开发入口

在新产品安装环境使用，不是旧 `content-agent`：

```text
collection-context --workspace <新工作目录> init
collection-context --workspace <新工作目录> add-link --url "<一条抖音分享文字或完整作品链接>" --browser-dir <库外本产品浏览器目录>
collection-context --workspace <新工作目录> add-link --url "<作品链接>" --browser-dir <库外本产品浏览器目录> --download
```

- 首条命令仅新空目录初始化；已有库不重复初始化。
- 默认仅入库平台文字说明、公开来源与作者；自动维护派生索引，可直接搜索和受控读取。平台描述不是转写或视频总结。
- `--download` 明确选择下载原媒体，并用自有 FFmpeg 流程准备音轨/画面；不会调用模型。视频和有序原图分支已接线，真实图文下载待单独验收。
- 需要桌面观察时可加 `--headed`，不是无桌面服务器登录已完成的证明。
- 媒体失败时返回 `download: blocked` 与安全错误，平台说明仍保留，不能把它当完整视频提取；不会自动调用模型补救。
- 图文、原音频和总结的模型处理继续使用已有固定输入/角色登记和持久任务入口。没有新增隐式费用或自动开关。

这是开发者入口，仍缺小白用户的安装、登录、配置/处理页面与后台执行；Windows 安全文件适配未完成，不能宣布三端可用。

## 下载边界

`PublicHTTP` 只接受显式允许的 HTTPS 域名，拒绝账号信息/非标准端口/越界跳转。每次跳转重新检查域名和 DNS；任何解析结果含非公开 IP 即拒绝。连接使用检查过的 IP，TLS SNI及证书仍校验原域名，避免校验后另一次 DNS 解析。此下载传输不继承环境代理，不发送浏览器 Cookie、Authorization 或 Referer。

媒体域名默认仅 `www.douyin.com`、`*.douyinvod.com`、`*.byteimg.com`；新增 CDN 需要审查，作品响应不能自行扩大域名权限。本次实际视频来自 `douyinvod.com`；图像 CDN 和图文需要真实样例补验。

一次最多5次跳转、单文件128MB、整作品512MB。空文件、超限、传输长度不符、压缩传输和HTML伪装媒体都会拒绝，不截断冒充完整。固定格式签名筛查不等于图像完整性解码，完整图像验证仍待完善。DNS解析自身的系统超时、浏览器资源流量/资源峰值及三端仍需更完整的运行验证；不宣称所有浏览器安全边界已经通过。

实际发现同一作品的第一个CDN返回403，第二个正常返回4,965,776字节MP4。新增最多3个页面提供的不同备用地址，每个20秒、有相同的域名/DNS/TLS/大小检查；不修改签名、不导入Cookie、不生成其他地址，429限流和安全拒绝立即停止。这里只对正常页面已给出的同一公开媒体做有界备用地址选择，不是付费模型重试。

## 独立连接与博主分页的新增开发切片

新增本地入口：

```text
collection-context --workspace <新产品库> connect-douyin --browser-dir <库外本产品浏览器目录> --wait-seconds 180
collection-context --workspace <新产品库> connection-status --browser-dir <同一专用目录>
collection-context --workspace <新产品库> sync-creator --url "<完整博主主页>" --browser-dir <专用目录> --limit 5
```

`connect-douyin`仅用于有桌面环境的可见浏览器，等待1～300秒；不读取喜欢/收藏或请求模型。`connection-status`只观察正常网页返回的本人资料；只有本人资料响应成功且账号身份有效，才返回认证成功。不导入第三方账号，不凭Cookie存在或登录按钮消失判成功。无桌面登录方式仍待验证。

博主入口不会从单作品自动扩展；默认5条，上限20，下载需显式加`--download`，没有模型请求。作者身份、正常网页请求中的作者/起始游标、分页连续性与游标推进均校验；跨页去重，超出本批的内容不入库。覆盖明确区分本轮数量/是否到数量上限/是否观察到列表末尾，仍不保证严格发布时间顺序、稳定快照或完整历史。平台置顶、删帖或排序变化不被补造。批次来源状态与入库关系已接线，但这是前台开发入口，还不是持久后台同步任务或自动增量同步。

新增`account.py`、`pages.py`及统一浏览器/CLI/入库接线；30项新增测试使用原创合成响应，涉及本人账号证明、其他用户资料不作本人身份、登录遮挡/关闭、作者错位、游标停滞/跨页去重、真实空列表与非法响应区分、失败状态与未知历史覆盖。完整456项通过，最新19.52秒；40个源文件mypy通过，Ruff/格式通过。**测试不证明真实账号登录或博主列表可用。**

## 后续接线：自有持久固定范围同步

该批新增 `workflows/synchronization.py` 和共享的 `SourceBatch`，没有接回第三方 CLI、签名程序、转写运行时或账号目录。范围配置、入库、阶段检查点、后台执行与模型适配仍使用同一个自有后端。浏览器、FFmpeg、HTTP/MCP 和 OCR 推理属于通用组件；用户选择的云模型负责推理，产品自行负责协议适配、分段、失败/用量记录与恢复。原生产流程未切换，不能把新切片的独立性写成整个旧项目已完成替换。

开发入口（真实私人列表尚未验证，以下是接口说明，不是要求自动执行）：

```bash
collection-context --workspace "<新产品库>" connection-status --browser-dir "<产品独立浏览器目录>"
collection-context --workspace "<新产品库>" configure-sync --kind liked --account-ref "<本人账号引用>" --limit 5
collection-context --workspace "<新产品库>" configure-sync --kind saved --account-ref "<本人账号引用>" --limit 5
collection-context --workspace "<新产品库>" configure-sync --kind collection --account-ref "<本人账号引用>" --collection-id "<稳定数字收藏夹身份>" --limit 5
collection-context --workspace "<新产品库>" configure-sync --kind creator --creator-url "<完整博主主页>" --limit 5
collection-context --workspace "<新产品库>" submit-sync --config-id "<上述某次返回的配置身份>" --idempotency-key "<本次固定批次唯一键>"
collection-context --workspace "<新产品库>" worker --allow-source-sync --browser-dir "<产品独立浏览器目录>" --once
```

注册配置/提交批次不访问平台；只开 `--allow-source-sync` 不提供/读取模型凭据，也不运行排队提取。本人引用来自实际正常账号响应，不接受猜测身份；指定收藏夹不能用名称代替身份。数量严格1～20，下载原媒体需在注册时显式 `--download`，仍不授权模型费用。同步采用正常网页观察，登录失效/身份改变/游标缺失或不连续会明确受阻，不把异常当0条成功。

每份已提交作品有检查点，重启后重新观察同一固定范围并核对已提交作品的源哈希；不重复提交已确认作品，范围变化/检查点损坏会阻塞。覆盖状态分别记录本轮数量上限与观察到列表末尾，完整历史仍为未知。取消后不导入后续作品，已确认资料保留；一份作品可以有多个独立来源关系。

首次固定范围批尚不包含定时同步。后续同日已补以下自有定时规则；用户收藏夹发现/选择界面、生产安装与系统常驻或三端私人登录仍未通过。本轮不重复弹出登录窗口，不读取旧生产收藏，不发真实模型请求。

## 后续接线：定时检查与原媒体复用

新增 `workflows/source_schedule.py`，复用原后台、文件事务、注册范围与检查点，没有新调度服务或第三方同步运行时。初始化仍关闭；每个已选择范围分别启用/暂停，默认60分钟，允许60～1440分钟。前一次成功完成后也要经过此间隔，时钟回退不补偿执行；停机数天只检查一次，不补跑错过的所有次数。每个范围最多一个定时待执行批次，已有同范围手动/恢复批次优先。只开模型授权的后台不会执行定时来源，只开来源授权也不会读取模型秘密或执行模型任务。

```bash
collection-context --workspace "<新产品库>" configure-auto-sync \
  --config-id "<已注册固定配置>" --enabled yes --allow-source-sync --interval-minutes 60
collection-context --workspace "<新产品库>" sync-settings
collection-context --workspace "<新产品库>" worker \
  --allow-source-sync --browser-dir "<产品独立浏览器目录>"
collection-context --workspace "<新产品库>" configure-auto-sync \
  --config-id "<已注册固定配置>" --enabled no
```

关闭后不新登记、启动后续定时批次；正在观察的浏览器批次不能保证即时撤回已发请求，取得结果后或下一份作品前检查暂停，保存已确认的作品检查点并关闭浏览器。重新明确启用同一策略只恢复这一有限检查点，手动任务独立。当前批次未结束时拒绝热换固定范围/间隔；取消仍为独立动作。

受阻、失败、部分完成或取消后不会由时钟无限重试；需要先解决原因，再使用 `configure-auto-sync ... --enabled yes --allow-source-sync --reset-blocked` 明确确认一次新检查。原任务和失败记录保留，确认不授权模型费用。旧的固定同步候选不认识新定时调度策略，会在任务启动前拒绝，不能忽略暂停后发请求。

定时检查采用有界重叠窗口：每次观察已选范围的最多N条，不在遇到一条已存在作品时提前停止；默认N=5、最大20，随固定来源配置保存。不能据此保证全部历史或高速新增都覆盖，也不把平台排序当严格时间顺序；扩展历史分页和真实平台效果仍待验收。

原媒体复用：来源正文与页面顺序/公开资源身份未变，且原始媒体、音频段和画面快照全部校验通过时，复用已绑定输入，不重复下载/FFmpeg准备。签名、过期参数不进入公开清单，也不因签名轮换重新处理。公共资源身份仅以主机/路径与明确视频/图片身份参数的哈希识别；同址、同身份远端静默替换文件不能只靠列表元数据检测，不能声称远端内容逐字节未变。资源身份改变时即使文案相同，也先使旧机器产物过期并撤销旧输入指针；内容变更或无来源绑定不能假装已下载。缓存坏损明确阻塞，不暗中下载来覆盖。原媒体与用户备注保留，不删文件、不自动重提取。

同步恢复检查点现在同时核对平台说明与公开资源身份。早期只记说明哈希的开发检查点不能被新包猜测为同一媒体，哈希不一致时明确阻塞；没有迁移真实生产库。最新安装证据及包/报告哈希统一维护在[实施记录](2026-10-01-抖音上下文MVP-实施与实际验收记录.md)。
