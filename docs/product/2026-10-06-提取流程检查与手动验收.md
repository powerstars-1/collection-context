日期：2026-10-06。入口：http://127.0.0.1:8790/

本轮检查范围：单条原媒体准备、音频转写、画面提取、总结、部分失败、任务重试和正文展示。保留已确认的工作台布局。本轮没有触发真实模型请求、批量同步或重新提取私人资料。

## 本轮修正

| 问题 | 调整后的行为 |
| --- | --- |
| 新图文发布的是 screen 正文，但阅读页请求 image，出现有结果却看不到 | 画面页优先读取实际 screen 产物，兼容旧 image 产物 |
| 有总结就显示可读，掩盖部分失败 | 区分“部分可读”和完整完成；已有正文保留，失败步骤可查看 |
| 转写、画面均失败，仍可能提交总结模型 | 没有可用提取正文时跳过总结，不增加无依据的总结请求；保留原文 |
| 提取前看不到无音轨、选帧失败等输入缺口 | 预览展示音频/画面数量及准备缺口，无音轨明确跳过 |
| 重开弹窗可能再次排入同一输入的提取任务 | 同输入已有排队/执行任务时后端拒绝重复提交；界面引导查看已有任务 |
| 任务详情只显示笼统失败，打开后进度不更新 | 显示各步骤的失败原因，并跟随任务刷新 |
| “准备画面失败”也能当作模型失败重试，但固定输入并不会改变 | 准备失败步骤不再列为可重试模型步骤；明确说明模型重试无法补回缺失输入 |
| 旧任务输入已更新时，重试预览一直显示“正在读取” | 在弹窗内显示拒绝原因，结束加载，明确本次没有提交新请求 |

单条保存原媒体与付费提取仍然分开：没有原媒体时可以只准备当前这一条，不要求重新同步整个收藏夹。音频、画面两路独立，某一路失败不抹掉另一路的结果。

## 仍然明确存在的限制

1. **复杂视频的画面准备仍可能触发选帧上限。** 本轮没有改变选帧算法或提高云端调用上限。超过上限时会保留可用音频并显示缺口，不能保证所有画面文字都被提取。
2. 当前“用深度视频，学会 AI 生成电影级大片”样例的画面证据只有 50、70、85 秒的三张人工指定测试帧；不是完整视觉扫描。不能用它证明全视频提取质量通过。
3. 已保存的任务固定使用当时的输入与模型。重试模型失败不是重新下载/重新选帧；准备缺口的完整修复需要重新准备输入，不应反复点击模型重试。
4. 本轮没有重新验证真实抖音登录、真实云端模型准确率或 Windows/Linux 原生安装。两项跳过测试也不计为通过。

## 统一手测清单

按照下面顺序一次完成即可，不需要逐项回来确认。每次确认提取前看一下显示的请求数量；实际费用由自己的模型服务计收。

| 场景 | 操作 | 应看到什么 |
| --- | --- | --- |
| 普通口播短视频 | 添加链接 → 打开资料 → 提取；如未保存媒体，先只保存当前这一条 → 确认提取 | 显示音频/画面数量；可关闭弹窗继续浏览；完成后分别看到总结、转写、画面文字 |
| 多页图文 | 添加一条图文 → 提取 → 打开画面内容 | 没有音频不是失败；能看到按图片顺序提取的正文，而不是空白页 |
| 无人说话的视频 | 添加无音轨视频，或无讲话但带背景音乐的视频 → 查看结果 | 无音轨跳过音频；有音轨不等于一定有人声，不应编造对话 |
| 部分失败 | 打开已有“部分可读”资料 → 补充提取 → 查看已有任务 → 查看详情 | 已有正文仍可读；能看到失败在哪一步。模型失败可以确认重试；准备缺口不能伪装成模型重试就能解决 |
| 关闭/刷新与重复点击 | 提交后关闭弹窗，刷新页面，再回到同一条资料 | 原任务继续可查；不因重复点击同一输入产生并行重复任务 |
| 关键教程页面 | 选一条有明确提示词/参数页的视频，记下出现时间；提取后对照画面正文和总结 | 核对名称、参数、提示词、顺序是否正确。若出现选帧缺口或漏页，单独记下时间点，不能仅凭“有总结”判为通过 |

反馈只需提供：资料标题或链接、操作到哪一步、预期内容、实际表现；漏画面时补充大致时间点。无需发送密钥。

下一步是这一轮统一手动验收。根据真实样例反馈继续修正选帧覆盖和模型质量，不提前宣称“全量不遗漏”。
