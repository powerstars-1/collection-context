# ADR-004: WeKnora 作为本地资料库的可选只读镜像

状态: 已批准

批准日期: 2026-09-15

## 背景

当前内容系统已经具备公众号、抖音、小红书和单链接入库能力，主要内容资产以 Markdown 与附件保存在外置盘。用户的日常入口以 Codex 对话为主，后续可通过飞书与 CC Connect 继续连接同一交互入口。

WeKnora 已完成 Lite 本地部署和小样本验证，能够提供知识库、文件夹、处理状态、原文下载、检索和网页问答。但如果将其作为主资料库或默认问答链路，会引入正文双份维护、模型重复调用、服务与数据库运维、同步漂移和上游升级耦合。

本决策承接历史 [ADR-002](../../archive/2026-08-09-workbench/decisions/ADR-002-Markdown资产与派生索引.md) 的文件资产原则：Markdown 与附件继续保存长期内容资产，数据库和第三方系统只能保存可重建索引、运行状态或镜像。此引用不批准旧 ADR 的其他选型；开源首发范围以 ADR-005 为准。

## 候选方案

### 方案 A: WeKnora 作为唯一文档主库

优点: 文档管理、解析、检索和问答入口集中。

缺点: 破坏本地文件事实源，现有入库链路需要迁移，任务与内容状态仍需自建，退出和恢复成本较高。

### 方案 B: 完全不使用 WeKnora

优点: 系统最简单，不产生镜像和同步成本。

缺点: 缺少适合人工浏览的知识库前端，也无法继续验证大规模语义检索和非 Markdown 文档管理价值。

### 方案 C: WeKnora 作为可选只读镜像

本地 Markdown 与附件是唯一事实源；WeKnora 只接收单向同步，用于网页浏览、搜索和可选问答。WeKnora 不承载业务任务、审核状态或唯一正文。

## 决策

采用方案 C。

系统关系:

```text
现有平台入库与文件处理
  -> 本地 Markdown / 附件（唯一事实源）
  -> 可重建同步清单
  -> WeKnora（只读镜像）
  -> 人工网页浏览 / 可选检索 / 可选问答
```

### 事实源与职责

| 数据或能力 | 负责组件 | 约束 |
| --- | --- | --- |
| 素材正文、转写、分析、内容稿 | 本地 Markdown | 唯一事实源 |
| 图片、视频、音频和原文件 | 外置盘附件目录 | 不要求全部复制进 WeKnora |
| 平台同步与单链接入库 | 现有内容后端 CLI/API | 不改走 WeKnora 入库链路 |
| 文件路径、哈希、处理和同步状态 | 本地派生索引 | 可从文件重建 |
| 人工浏览、文件夹和知识库视图 | WeKnora | 可选前端，不反向写回 |
| 本地精确搜索与内容分析 | Codex 直接读取文件 | 默认路径 |
| WeKnora 原始检索 | `search_chunks` / `knowledge-search` | 仅按需使用，不调用第二次答案生成 |
| WeKnora 网页问答 | `knowledge-chat` | 用户主动使用时启用 |
| 任务、审核、版本和运行状态 | 自有业务模块 | 不写入 WeKnora 内部业务表 |

### 同步原则

- 只允许 `本地 -> WeKnora` 单向同步。
- WeKnora 中的正文不得作为本地文件更新来源。
- 单条同步失败不得使本地入库失败。
- 计划在入库成功后执行一次尽力而为的单条同步。
- 计划每周执行一次全量对账，修复漏同步、内容变化和失败记录。
- 周期任务涉及本机外置盘和本机服务，正式实现时使用 macOS `launchd`，不使用 Codex cron。
- 对账使用内容哈希和稳定文档标识，不逐篇调用大模型比较正文。
- 本地文件消失时先标记镜像待归档；默认不在第一次发现时永久删除 WeKnora 文档。
- 同步程序必须可重复执行，同一文件和同一版本不得产生重复镜像。

计划中的同步清单至少保存:

- 本地绝对路径或工作区相对路径
- 稳定资源 ID
- 内容哈希与文件修改时间
- WeKnora 知识库 ID 与文档 ID
- 最近同步时间
- 同步状态与最近错误
- 本地缺失时间与归档状态

### 同步内容范围

- 公众号文章同步标题、作者、发布时间、原链接、正文 Markdown 和必要图片引用。
- 抖音、小红书同步标题、文案、转写、画面文字、总结、原链接和封面信息。
- 大体积视频、音频和重复附件默认不复制进 WeKnora，只保留本地位置和可读衍生内容。
- PDF、Word 可保留原件与解析后 Markdown 的关联；是否复制原文件由后续小样本验证决定。
- 任务状态、审核事件、财务数据和其他结构化业务记录不进入 WeKnora 文档镜像。

### 查询与问答路由

- Codex 在本机工作时，默认使用 `rg`、文件路径和直接读取 Markdown。
- 只有在跨大量文档的语义召回确有收益时，才调用 WeKnora 的原始检索接口。
- 当前对话负责阅读命中片段和生成答案，不默认调用 WeKnora 的答案生成模型。
- 用户直接使用 WeKnora 页面时，可以选择其独立问答能力；其回答属于派生结果，不覆盖原文。
- 未来总 MCP 暴露中性的 `search_documents`、`read_document`、`list_documents` 和 `get_document_status`，不得要求调用方依赖 WeKnora 产品概念。

### 部署与数据库

- 当前继续保留 WeKnora Lite 隔离实例和测试库，不立即迁移正式资料。
- 暂不因本决策迁移 PostgreSQL。
- 如果后续从 Lite 迁移 PostgreSQL，可以与其他系统共用 PostgreSQL 服务实例，但必须使用独立数据库、独立账号和独立备份边界。
- 迁移前必须核对 PostgreSQL 版本、`pg_trgm`、`vector` 和实际检索方案需要的扩展，不直接假设普通 PostgreSQL 等同于官方 ParadeDB 镜像。
- PostgreSQL 迁移不能改变“本地文件是事实源、WeKnora 数据可重建”的边界。

### 远程访问边界

- 当前 WeKnora 监听 `127.0.0.1`，只代表本机可访问。
- 外出访问应使用受控的远程桌面或私网通道；不得为了方便浏览直接把 WeKnora 端口暴露到公网。
- 飞书与 CC Connect 连接 Codex 的路线不依赖 WeKnora 对公网开放。

## 当前验证状态

已验证:

- Lite 服务、知识库创建、5 份合成文档处理和原文读取。
- 文档移动、下载、重新解析和限定文档范围检索。
- 原始检索在本轮小样本中的单次观察约为 143–504 ms。
- `mimo-v2.5` 独立模型连接检查成功。
- 最小问答和原四问复测均完成并写入引用；单次约 18–20 秒。

尚未验证或尚未实现:

- 正式业务文档的批量镜像。
- 入库后单条同步和每周全量对账。
- 内容哈希、稳定 ID、归档宽限和漂移修复。
- PDF、Word、公众号图片和较大附件的镜像边界。
- 服务重启、备份恢复、长期运行和远程访问。
- 20–30 份以上真实资料的检索质量与维护成本。

## 影响

正面影响:

- 保留 WeKnora 前端浏览体验，不改变现有入库和内容生产流程。
- 避免所有 Codex 查询都绕经第二个问答模型。
- WeKnora 可以随时重建、暂停或替换，不锁定总 MCP 接口。
- 正式改动集中在同步适配器、同步清单和少量状态展示。

成本与风险:

- 需要维护一份可重建镜像和周期对账。
- WeKnora Lite 当前仍有批处理 `chunks.seq_id` 冲突风险和 SQLite 功能迁移缺口。
- 镜像延迟意味着 WeKnora 页面可能暂时落后于本地事实源。
- 用户必须能区分本地原文、WeKnora 镜像和模型派生回答。

## 实施范围

本决策批准架构方向，不代表同步功能已经完成。

最小实现只包括:

1. 定义同步清单和稳定资源 ID。
2. 完成少量真实 Markdown 的单向导入、更新和跳过验证。
3. 增加入库后单条同步的可选动作，失败不阻塞主流程。
4. 增加每周 `launchd` 对账任务和可读运行记录。
5. 在现有控制台展示镜像同步状态和手工重试入口。

暂不包括:

- 双向同步。
- 全量历史资料一次性迁移。
- 业务任务写入 WeKnora。
- PostgreSQL 迁移。
- 公网部署。
- 将 WeKnora 设为总 MCP 的强依赖。

## 重新评估条件

- WeKnora 镜像长期无法保持一致，维护成本超过浏览收益。
- 现有控制台已经可以满足全部人工浏览需求。
- 文档规模和语义查询频率证明 WeKnora 原始检索有明显收益。
- 出现多个无法直接访问外置盘的稳定客户端或协作者。
- 需要多用户权限隔离、自助问答或集中式知识服务。
- Lite 的并发、迁移或恢复问题要求迁移 PostgreSQL或替换组件。
