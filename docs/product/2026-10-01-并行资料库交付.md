# 并行资料库交付：自动索引与一致备份

日期：2026-10-01
分支：`codex/context-library-management`
范围：R07 / R13 的独立资料库子集；未接管私人库、登录态、模型密钥、同步或发布。

## 1. 本批实现

- 资料事务会比较提交前后的资料版本。只有条目、来源关系、排除状态、媒体输入或产物发生变化时才自动维护索引；任务进度和用量记录不会无效重建索引。
- `search` / `read` / `status` 仍为只读，不在查询时修复、重建或触发提取。索引失效时明确报错，不返回旧版内容。
- 每份已提交资料自动生成 `content-vault/00_素材收件箱/抖音/<资料ID>.md` 可读入口，列出稳定引用、来源关系和已提交产物。该页是派生入口，不代替提交清单。
- 自动索引在资料提交后失败时返回 `index_maintenance_failed`，明确说明资料已提交、不应重复入库，并给出显式重建索引的下一步。
- 新增带完整 SHA-256 清单的 ZIP 备份，只包含已提交正文/产物、来源关系、任务清单与用户明确选择的媒体范围。
- 备份不包含产品访问口令摘要、平台登录目录、模型密钥目录、派生索引和暂存物。备份前必须关闭自动同步与自动处理。
- 恢复不直接解压归档：先检查重复成员、越界路径、链接、加密成员、文件数/大小、状态哈希和每个文件哈希，再写入同父目录的隔离暂存库。完成提交校验与索引重建后，才原子移到新路径。
- 恢复保留原库 ID，默认关闭自动同步/处理及来源定时。不恢复密钥或登录态。失败时删除本次新建的隔离暂存，不修改已有目标库。

## 2. 独立 CLI

不改动共用 `cli.py`，本批提供独立模块入口：

```bash
PYTHONPATH=backend/src python -m collection_context.library.backup_cli backup \
  --workspace "<资料库路径>" \
  --output "<新备份.zip>" \
  --media all

PYTHONPATH=backend/src python -m collection_context.library.backup_cli restore \
  --archive "<备份.zip>" \
  --destination "<新路径或空目录>"
```

`--media` 必须明确选择：

- `all`：包含已登记的原媒体、音频段和画面快照，保留处理输入清单。
- `none`：只保留文字、来源、产物和任务历史；清单逐个列出省略媒体的路径、字节数和哈希。未完成的处理任务在恢复库中标为阻止，不会因输入缺失自动重发或计费。

## 3. 验证边界

专项测试覆盖：内容提交后自动索引、只读查询不写入、排除后不可检索，索引失败后已提交内容可恢复，全媒体/无媒体备份，异路径恢复，秘密/索引/暂存排除，恶意越界归档拒绝，损坏备份失败不动目标，非空目标拒绝，以及独立 CLI 往返。

本批仅在 macOS 当前文件安全适配层上实测。Windows、Linux x64、Linux ARM64、外置盘掉线、磁盘空间耗尽及大库性能仍未在本工作包实际验证，不从 macOS 结果外推。

## 4. 未包含

- 未把备份命令接入共用 CLI、HTTP 或管理页；该整合由总控处理。
- 未实现单份资料导出、回收区/永久删除、受控编辑冲突和旧 `m1:` 引用映射。
- 未使用私人库、真实登录、云模型或生产后台；无模型请求与费用。
