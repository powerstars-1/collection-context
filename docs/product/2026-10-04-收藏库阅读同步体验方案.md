# 收藏库、阅读与同步：本轮体验方案

日期：2026-10-04。状态：调研与样稿方案已落实到 8790 实际开发页面，并完成本轮界面点测。不是全量同步、付费模型质量或开源发行验收。

## 1. 本轮判断

用户保存内容后再次进入，核心诉求是认出内容、知道它讲了什么、读到可复用步骤，最后把它交给自己的 AI。添加链接是一个短动作，应在收藏库顶部占一行；阅读时不再重复占用正文区域。

当前问题不只是按钮故障。`Library.jsx` 把 `LinkComposer` 放在 main 的常驻开头；该组件包含大标题、说明、三行输入框、选项及记录。选中资料后它仍在。阅读区又将标题、来源、提取按钮、嵌套内容页签和技术状态分别装进多个卡片。页面按实现模块分块，缺少按用户目的排列的信息优先级。

本轮也实际打开了 8790 的收藏夹、选中“深度视频”条目，并进入同步页核对。现场库共 9 条；当前条目的大标题是整段平台文案，不只是作者的简短原题，导致正文页签落到首屏下方。同样的文案又在原文重复。同步页面中“收藏”“ai”是部分完成，喜欢为同步完成；来源结果藏在账号配置与博主表单后面，首次可见区域无法直接知道这次到底拿到了什么。设计样稿中的三条总结来自旧库，不代表这 9 条已完成模型提取。

保留原有 React 组件与自有后端，调整布局、呈现及动作衔接。不换框架、不做第二套客户端、不重建私人库。

## 3. 推荐版式和视觉规则

- 应用壳随窗口展开；侧栏约 184–224px，不强迫所有内容堆在狭窄三栏中。
- 收藏库主内容设最大宽度，推荐 1120px；同步页约 960px；阅读正文约 760px。宽屏留白，窄屏自然折行，避免长行和无边界拉伸。
- 顶部链接入口桌面端约 50–56px 高，一行输入和一个“添加”按钮。粘贴分享文字也支持；Enter 提交，输入法组合态不误提交。
- 浅灰画布、白色内容、浅蓝账号/选中区域。依靠底色、留白、标题共同分区，边线只负责局部边界。
- 蓝色突出当前主动作；白底深字为次动作；绿色“可读/已完成”、橙色“有缺口/待处理”、红色“失败”，颜色均配文字。不能把按钮文字灰到不可辨认。
- 列表默认短标题两行以内、一句内容要点、作者/保存时间和一个有意义的状态。原平台长标题保持完整数据；阅读页正常换行，标签与正文描述不塞进展示标题。无 AI 标题时不擅自改作者标题，允许保留可展开的原题。
- 小窗口阅读转为单列；重要动作不依赖 hover。搜索和链接输入不合并成一个猜意图的框。
- 不做内置知识库聊天模型：用户已有 Agent 承担理解与问答，产品负责内容保存、处理、找回和提供证据。

## 4. 页面、按钮及下一步

| 页面/状态 | 用户看到什么 | 主动作和结果 |
| --- | --- | --- |
| 首次进入空库 | 一行链接输入；下方用一个清晰空态提供“连接抖音” | 添加后立即出现该条任务，成功后有“查看内容”；不逼用户先同步全部收藏 |
| 已有内容 | 最近保存、短标题、一句要点、可读/待处理状态 | 点击标题或“阅读笔记”进入内容；搜索可命中已保存的正文，不只查标题 |
| 链接处理中 | 已接收 → 保存中 → 已保存；任务在页面离开后仍能恢复 | 同一条避免重复提交；失败时保留输入并可重试，不能显示成完全成功 |
| 已保存、尚无笔记 | 原作品与作者；“原视频已保存，还没有笔记” | 已配模型：生成笔记；未配：设置模型。设置后返回原资料，不让用户再找一遍 |
| 有总结 | 正文标题、简短来源、总结默认可读 | 总结 / 转写 / 画面文字 / 原文直接四个页签；复制当前正文，打开原作品 |
| 有转写但无总结 | 先给可读转写，清楚说明总结未生成 | 仅生成总结时不重新转写；不把平台说明当作完整视频正文 |
| 部分完成 | 哪些可读、哪些缺失；可读结果仍保留 | 针对缺失环节处理；重新计费前显示范围，不默认重跑全部 |
| 生成失败 | 简短可操作原因，原媒体仍在 | 修改配置或重试；进度到完成后留在当前资料，结果直接可见 |
| 搜索未命中 | 原查询、换短关键词建议、清除搜索 | 不把用户机械送去同步；保持原有来源和筛选语境 |
| 同步页未连接 | 账号区域和“连接抖音”，来源暂不可选 | 登录完成自动识别状态，再选择来源；收藏夹暂不可用不阻挡喜欢/收藏 |
| 同步页已连接 | 账号浅蓝区；喜欢、收藏、指定收藏夹按行；博主次级入口 | 勾选来源 → 同步选中来源；数量、原媒体、自动生成在同步选项内 |
| 同步结束 | 分来源新增/重复/失败，不冒充真实喜欢时间 | “查看本次内容”带来源/任务筛选；保存与生成结果分开显示 |
| CLI 接入 | 已安装/需要安装两项，一段可复制说明 | 用户把说明交给支持本机命令的 AI；正式页自动填入已确认程序和库路径 |

同步数量、保存原媒体、自动提取仍保留，只逐步展开；不是删除能力。账号退出只注销平台会话，已有资料不清空。

## 5. CLI 首轮边界

用户本轮明确先把 CLI 做好，MCP 暂时退出首轮界面和验收优先级。现有后端适配器不需要为了改变入口而贸然删除。

新产品的实际命令为 `collection-context`，不是旧库工具 `content-context`。参数顺序以当前 `backend/src/collection_context/cli.py` 为准：

```text
collection-context --workspace <库路径> search --query "动画 分镜" --limit 3
collection-context --workspace <库路径> read --ref <返回的引用> --artifact summary
collection-context --workspace <库路径> status --ref <返回的引用>
```

已安装说明让 AI 检查环境、少量关键词检索、按引用阅读、保留来源与缺口。读流程不另建产品口令、不调用平台、不调用模型；明确添加/同步/付费提取属于另一个用户请求。

安装说明先取得用户提供的源码或安装包，依据现有安装文档安装，再用 `--help` 和只读查询验证。当前没有公开发行地址，不能捏造 `pip install` 公共包或 GitHub 下载链接。独立安装环境与源码/打包验收保留，不向用户展示整套工程参数。

## 6. 样稿中的三条真实内容

1. **Clawd 动画教程**：先定风格与样图，再定剧情、写分镜，画面/配乐/音效共用节拍表，最后按具体不满意点迭代。来自既有 `7689743418313952538/内容总结.md` 与转写。部分分镜和背景参数仍待核对。
2. **深度视频换景/换装**：原视频提供动作/运镜，深度视频减少视觉干扰，参考图控制目标角色/环境/光线，先短片测试再检查一致性。来自既有 `7687931599270333730/内容总结.md`。专名和版本存在音画差异，部分提示词遮挡。
3. **Hypit 视频结构复用**：拆镜头，按语音时间点编排画面/字幕/音效，复用骨架后替换人物或产品。来自既有 `7690777179302415642/音频转写.md` 的本次归纳。转写存在时间缺口和“Happy”专名疑点，不称完整教程。

这些是旧库已有材料的重新呈现，本次零新模型请求、未写回新库、未使 8790 的处理状态变成已完成。不把参考视频里的模型版本、价格或作者声称的效果当成本次核实事实。

## 7. 本轮交付与后续实施

本节保留样稿阶段的实施计划；本轮用户确认后的实际完成情况见第 8 节。

本轮交付可点击样稿：收藏库、阅读、同步来源、CLI 说明；列表/卡片切换、关键词搜索、内容页签、来源选择；可调整阅读状态（正常/待生成/失败）与主区域最大宽度。样稿不访问后台、不执行同步、不收费。

下一轮只沿用现有组件实施这些页面，分为：

1. 缩小 `LinkComposer` 并离开阅读区域；整理库列表、搜索/空态。
2. 整理 `Evidence` 的直接页签、可读排版与当前内容复制；结果/缺口/主动作衔接。
3. 整理 `Sources` 的账号、来源选择、进度与结果去向。
4. 把 `Access` 主界面改为 CLI 安装/使用提示词，动态使用后端返回的真实执行路径。
5. 用新用户空库与现有资料库分别做“添加 → 保存 → 阅读”和“连接 → 同步 → 查看本次内容”验收。独立验证真实内容质量；不再用漂亮静态样稿代替真实闭环。

不继续扩展协议层、企业权限、额外客户端或新数据库。实际实施完成前不声称页面已改好。
