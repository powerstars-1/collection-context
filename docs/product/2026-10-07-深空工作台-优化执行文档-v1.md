## 3. 文件职责与实施策略

### 3.1 不引入另一套组件库

继续 React、现有路由与图标。扩展现有 `ui.jsx`，逐步让原生 button 使用同一组样式类/语义属性；不为了一个主题重写整个业务页面。

建议固定入口：

```jsx
// 目标接口，尚未实现；支持原有 class 导出过渡。
<Button variant="primary|secondary|ghost|danger" size="md|sm"
  busy={false} disabled={false} icon={Icon}>操作名称</Button>
<IconButton label="打开原内容" icon={ExternalLink} />
<Dialog size="standard|extraction|task|image" title="...">...</Dialog>
```

Button 的 type 默认 button，提交表单显式 type=submit。转发必要的 aria、ref、事件与 disabled；busy 不能删除按钮文字；危险样式不自动代替业务确认。现有原生 `<a>` 保持链接语义，可以共用视觉类，不包在 button 里。不要做“万能组件”接管全部业务。

### 3.2 样式归属

| 归属 | 允许声明 | 不允许声明 |
| --- | --- | --- |
| `cosmos.css` | 全套 `--ds-*` 与旧变量别名、全局字体、基础表面 | 每个页面单独调 primary 色 |
| `space-ui.css` | Button/Input/Tab/Menu/Notice/Dialog 与页头/卡片表面状态 | 场景节点坐标、数据逻辑、再定义另一套 token |
| `atmosphere.css` | 背景层、页型星图强度、z-index | 按钮字体、业务页内边距 |
| `preview.css` / `neural.css` / `flow.css` | 现有页面/场景几何与响应式 | 残留绿底、金属渐变、通用按钮 active transform |
| `workspace-library.css` | 阅读、收藏专属布局与内容排版 | 覆盖通用按钮材质、白底代码块 |
| `live.css` | 来源、任务分支、设置等特有结构 | 新增通用按钮色值；全局 `.bg-white !important` 大范围补丁 |

可在同文件按层组织，不强制新增目录。先移除 JSX 中冲突的亮色/缩放 utility，再删对应深色补丁；每批页面通过才删其旧覆盖。未触及的共享样式不得盲删。最终要求“一个属性有明确所有者”，不是单纯减少文件数量。

### 5.2 数值验收

- 字体、间距、高度、圆角：与规范差值≤1 CSS px。动态文案/自适应宽度以规则计算，不以截图肉眼估计。
- 正文字号最低12，正文主体15/16；按钮图标同一行。44px触控区不得互相覆盖。
- 所有透明视觉层只影响装饰。取实际合成背景测对比，而非仅检查变量名。
- 正常文字≥4.5:1，大字≥3:1，关键控件边界/焦点≥3:1。低对比分隔线不得被当作唯一操作边界。
- 菜单、模态、Toast叠层正确，page-scroll不会裁切菜单；main保持不制造错误堆叠上下文。
- 无页面级横向溢出；代码/表格/页签允许各自受控横滚。
- 无新外部素材请求；星图失败静态降级；功能不依赖素材下载完成。
- 测试时不新增同步/计费请求；视觉层不能引入轮询。

每批记录一条，不堆“已优化”总结：

```text

剩余问题：具体项，不写泛泛“继续打磨”
```

以下情况停止扩展，先处理当前项：

1. 缺素材许可、路径无法打包、主视觉样张未经审阅。
2. 为修样式需要改变实际数据语义、删除用户文件或新增付费调用。
3. 页面无法截图/操作，只能凭CSS判断。可以完成局部代码/测试，最终状态必须停在“未视觉验收”。
4. 老代码有无关故障或他人并发修改，记录证据，不能回滚整仓。

回退：只回退本轮已记录的文件块或本轮提交，不用 `git reset --hard`，不覆盖用户原有改动，不清库。新样板失败时保留真实入口现状，不让用户承担半套换肤。
