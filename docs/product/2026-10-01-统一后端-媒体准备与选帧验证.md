# 统一后端：媒体准备与选帧验证

2026-10-01，开发切片；完整 MVP 仍在实施。本页记录自主重写的媒体基础，不把它称作已经接通的转写服务。

## 1. 原创实现和模块责任

用户再次强调：同步、转写、模型接入与流程管理应进入我们自己的统一后端，既有项目用于理解输入输出和实践经验，不成为新产品运行依赖。

当前实现为 `backend/src/collection_context/infrastructure/media.py`：由自有代码探测视频、设定处理上限、分段抽音频、扫描画面变化、决定候选、按同一采样序列解码证据原图并报告覆盖缺口。底层仅显式调用 FFmpeg/FFprobe 通用媒体工具；不调用 dYm、All-IN-ONE、百炼 CLI 或旧 `app` 的任何流程。云端协议仍由自有 `processing/models.py` 直接发送 HTTP；本轮未发送云端请求。

职责继续分开：`infrastructure` 负责解码和 CPU OCR 适配，`processing` 消费音频/画面证据形成提取，`workflows` 负责持久阶段、预算、取消和恢复，`library` 负责提交与查询。检索不启动媒体处理。当前媒体准备尚未接进任务执行器或网页按钮，不存在新的生产转写入口。

## 2. 已实现阶段契约

| 阶段 | 输出 | 失败/限制 |
| --- | --- | --- |
| 显式媒体快照 | 原文件 SHA-256、独立临时副本、解码器版本、处理策略哈希 | 输入为空/过大或工具缺失拒绝；不读取第三方登录目录或全局模型配置 |
| 视频探测 | 时长、尺寸、选定视频/音频轨 | 无可靠时长、尺寸过大或格式不支持拒绝；无音轨与解码失败分开 |
| 音频准备 | 16kHz 单声道 PCM WAV；每段 ID、起止区间、解码时长、哈希、重叠标记 | 数量/大小超限或解码覆盖不足显式失败；不生成虚假的逐字时间戳或空成功转写 |
| 候选扫描 | 首尾、全局变化、局部变化、细微像素变化、覆盖锚点；帧 ID、采样序号及原因 | 候选数量超限阻塞，不能削减后称完整；采样和解码不完整均报错 |
| 原图解码 | 同一采样滤镜与序号，一次解码按顺序交付 PNG、哈希和候选关联 | 每帧大小、总输出及执行时间受限；帧流缺失/不完整拒绝 |

处理器版本为 `local_media_v3`。策略哈希包含媒体策略及 FFmpeg/FFprobe 返回的版本，媒体输入哈希另记，不能仅凭文件名复用结果。

当前默认策略：源文件上限128MB，时长两小时，像素数8,294,400；每秒2帧缩略扫描，候选最多240；音频每段240秒、重叠1秒；单段WAV上限16MB，单图32MB、最长边2560像素；单次解码120秒。这些是显式保护值，不等于两小时复杂视频已经通过质量和耗时验收。模型自身的限制仍需单独校验，不能根据本地上限直接上传。

进程通过固定参数和 `shell=False` 调用，禁用交互输入；仅放行本地文件/管道协议和限定容器格式，关闭 MOV 外部数据引用。模型/平台环境凭据和 FFREPORT 不传给解码子进程；原始错误日志不回显；输出以有界队列流式消费，超时终止本次自有子进程。临时副本仅存在于本次准备会话，退出后清理，不改动原文件或资料库。

这不是操作系统沙箱：FFmpeg本身及其运行库仍属可信依赖，原生解码的组合峰值资源、服务器最小权限及三端实际运行仍需后续验证。

## 3. 真实测试发现和修正

固定数据完全原创：10段视频、50个人工定义的页面，含横/竖屏、中文和英文工具词、代码、深色/低对比度、底部局部变化、位移页面、0.6秒短页和20秒后才出现提示词的回归样例。两段有合成纯音，其余无音轨；纯音只能验证抽音轨和分段，不是语音转写精度样本。页面字幕变化仅是有限静态样例，尚无真实高频字幕/复杂动画覆盖。

保留原始失败，不改人工标注掩盖问题：

1. `local_media_v1` 普通平均/局部阈值：采样没有漏标注页，选择漏27页，OCR也漏27个编号。只改一个数字时，整体画面差异太小。
2. `local_media_v2` 加细微变化检查：其余页面补上，短页仍漏1页。定位到扫描的帧率转换与原图的独立时间跳转不一致，选到的缩略图和拿去识别的原图可能不同。
3. `local_media_v3` 细微变化检查、统一采样滤镜、按同一采样序号一次解码原图：在本固定集，50页均有候选，50个页面编号被实际 CPU OCR 识别到。采样、选择和 OCR 编号缺失分别为0。

源代码实跑报告在私有验证目录 `media-validation/media-smoke-fn8t01v5/report.json`：71张候选原图，含重复证据和讲解前段；总27.651秒，OCR初始化4.948秒；Python/OCR父进程生命周期内峰值约620MiB，不含并行 FFmpeg 的组合峰值。FFmpeg 8.1.1 / RapidOCR 3.9.2 / ONNX Runtime 1.30.0 CPU，macOS ARM64；这不能推断 Windows、Linux 或其他硬件结果。

该验证检查“标注页是否被选到”和“页面编号是否能从对应原图识别出来”。它不是全文字符准确率，也不是所有关键事实的质量验收。真实动画、滚动长文、缩略后消失的小字、短于采样间隔的闪页仍可能漏；细微像素规则在噪声/运动视频中会保留很多候选，后续还需 OCR 辅助去重和有标注的困难样本。不能将某一固定集的100%宣传成任意视频无遗漏。

当前候选包安装后又从仓库外实跑一次，`--require-installed`确认导入的是隔离环境site-packages；`installed-media-validation/media-smoke-4mxrr0lo/report.json`仍为采样/选择/OCR编号缺失0，云请求0。完整回归311项通过，新模块24文件类型检查及格式/静态检查通过。候选包、检查点及MCP/网页复验见[实施记录](2026-10-01-抖音上下文MVP-实施与实际验收记录.md)。

新装隔离环境的首次报告总115.584秒，其中OCR初始化91.925秒；父进程峰值约592MiB。随后同一安装环境的新进程离线初始化8.983秒，适配器导入0.184秒；通过进程内网络拒绝审计验证，网络连接尝试0。不能把首次延迟直接归因于网络或某个库，冷启动原因仍待分项定位。生产实现需要一次加载复用，并在界面显示初始化进度，不能假定每段任务的初始化都只要5秒；该耗时问题不因页面召回通过而忽略。

扫描覆盖明确返回 `ocr_state=not_applied`、`complete=false`：CPU OCR 在本次测试中用于核对候选原图，尚未成为正式选页/去重决策。时间是名义采样网格，未声称原始视频精确呈现时间戳。未完成的功能不借测试报告包装为已实现。

## 4. 可重复验证和下一步

开发环境带 Pillow、已核对的本地 OCR 权重和 FFmpeg 后，从 `backend` 运行：

```bash
PYTHONPATH=src python tools/media_smoke.py \
  --output '<新的私有测试目录>' \
  --models '<已核对的本地OCR权重目录>' \
  --font '<可用的中文字体文件>'
python -m pytest -q tests/test_context_media.py
```

生成内容仅在新建测试子目录；不下载私人视频、不登录、不读取模型 Key。脚本返回非零表示固定样例有缺失，报告保留全部候选和失配信息。发行包安装后的验证可以从仓库外运行同一脚本并加 `--require-installed`；需显式安装可选 OCR 依赖和测试用 Pillow。

下一步接持久任务与阶段结果，抽音频、视觉、总结分别记录输入/策略、请求意图、实际用量和缺口，复用已成功段。先保存本地准备结果再调云请求，不在解码回调中等待模型。之后做真实语音与困难画面质量验证、精度/重复率和资源开销，再开放管理页入口；原生产链路仍保留。

参数依据核对了官方 [FFmpeg 选项说明](https://ffmpeg.org/ffmpeg.html)、[协议白名单](https://ffmpeg.org/ffmpeg-protocols.html)与[帧率转换滤镜](https://ffmpeg.org/ffmpeg-filters.html#fps)。官方文档只用于工具用法，质量结论来自本项目测试。
