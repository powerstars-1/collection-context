# 收藏上下文：小白用户实际体验审查

日期：2026-10-03。范围：当前管理页面的首次使用、保存、提取、阅读、找回与 AI 接入。本轮是体验审查，未修改业务代码或界面，不代表真实提取质量验收通过。

## 结论与审查视角修正

用户进一步指出：问题首先不是某个技术步骤出现断点，而是产品没有先设计完整的用户体验流程。接受这个修正。本文件前半部分以用户目标重新定义体验；后半部分的实际操作与技术错误只是现状证据，不能代替体验设计。

当前组织方式主要按实现模块展示收藏库、同步、设置、任务、AI 接入。用户必须自行理解这些模块、判断操作顺序、把它们串成流程。首页加入输入框并没有自动解决这个问题。**即使所有请求成功，用户仍需要自己编排使用步骤，因此不能只以修完报错作为产品验收。**

最重要的改动不是增加按钮或换视觉框架，而是先让每个使用场景都有明确的入口、预期结果、下一步、离开后返回方式，再让页面和按钮承担这些职责。

## 用户体验流程：先定义用户要完成的事

### 场景一：第一次进来，先得到一份真正可用的资料

用户想：「听说这个能把我的收藏留下来，以后找得到。我想先试一条。」

第一屏应回答三件事：这是把收藏变成可查找、可复用资料的工具；我可以粘贴一个链接试用；我也可以导入自己已有的抖音收藏。首页主要输入区保留，但旁边要有清楚的「导入我的抖音收藏」入口，不能用含义宽泛的「去同步内容」承接宣传中的主要需求。

正常体验：

1. 用户粘贴分享文字并点「保存」。
2. 当前区域显示正在保存什么，输入不会因为登录或配置步骤丢失。如需抖音登录，在这条流程中引导本人登录，完成后回来接着处理。
3. 保存完成展示作品名、封面或类型，以及「已保存」；明确这只是保存，尚未形成笔记时提供「生成转写和总结」。不要求用户自己发现任务页。
4. 第一次生成需要模型而未配置时，在当前资料上给「配置模型」入口，完成后回到这条资料继续。只在需要的时候说明填什么、去哪里获取；不先让新用户阅读全部模型协议与高级参数。
5. 一次明确确认承接转写、画面文字、总结，不让用户逐个编排。告知所用服务和可能费用；未确认不自动计费。
6. 当前资料显示处理中和阶段进度，允许用户去做别的事。离开、刷新后仍能回到这条资料，看到最新结果。
7. 完成后默认展示有价值的笔记，总结、转写、画面文字都能明确找到。下一步是阅读、复制、回看来源或继续保存，不是「到任务列表看已完成」。

没有配置模型也能完成仅保存，但必须明确告诉用户得到的是链接/平台说明/原媒体中的哪些内容，不能把这称为已理解视频。

### 场景二：把我已有的收藏整合进来

用户想：「我有很多收藏，不想挨个贴链接。」

体验顺序：**导入我的抖音收藏 → 登录本人账号 → 选择收藏/喜欢/具体收藏夹 → 确认范围 → 在当前流程看导入进度 → 直接查看导入的资料**。

- 用户选择来源名称与范围，不研究账号 ID、分页游标和后台任务。
- 首次少量导入要明确说「近期多少条」，不能让用户误以为已经导入全部。
- 完成结果应给「查看这批资料」「整理这批资料」；继续导入历史如果有能力就给明确入口，没有实现不能放一个空按钮。
- 自动同步、自动整理是后续便利选择，彼此分开，说明启用范围；不是第一次导入必须完成的设置作业。
- 喜欢/收藏/收藏夹的筛选是帮用户在自己熟悉的分组里找内容，不要求理解一条作品的内部关系模型。

### 场景三：过几天，我记不住标题，但想把教程找回来

用户想：「我记得收藏过一种保持人物一致的方法，现在要用。」

体验顺序：**搜索 → 看相关内容摘要 → 打开命中的总结/转写段落 → 复制方法或提示词 → 必要时回看原作品**。

- 搜索结果不能只给标题，要告诉用户为什么是这一条、命中了什么内容。
- 找不到时帮助换词、清掉限制或扩大范围，而不是让用户去重新导入收藏。
- 页面现有能力是关键词检索，不能用一个搜索框假装已实现任意自然语言理解。宿主 AI 可以改写/拆分查询；具体能力需实测后再宣传。
- 资料页面中的价值是可拿走使用的内容：教程的步骤/提示词、观点的要点及来源。只展示「已经转写」或内部文件状态不足以满足目标。
- 摘要与提取保持来源证据，不能为了显得完整补造来源里没有的步骤。

### 场景四：以后让自己的 AI 直接找资料

这是可选的后续使用方式，不是保存第一条的前置条件。

用户选择自己正在用的具体客户端，看到适用的接入步骤与测试问题；产品明确连接成功的验证方式。不以展示 MCP JSON 或 HTTP 请求示例作为小白接入已经完成。保持与已有 Personal Agent 协作的定位，不另外新建一套聊天服务。

## 页面与操作应该承担的职责

| 位置 | 用户到这里要完成什么 | 主要操作 | 操作后承接什么 |
| --- | --- | --- | --- |
| 首页/收藏库 | 留下一条内容，或导入已有收藏 | 保存链接、导入我的抖音收藏、搜索资料 | 当前区域显示保存结果并打开对应资料 |
| 导入流程 | 明确哪些内容进入我的库 | 登录、选择范围、开始导入 | 显示这批资料与整理入口，不要求另找任务 |
| 资料详情 | 看懂这条内容，并拿去使用 | 生成笔记/查看总结、转写、画面文字；复制；看来源 | 处理与阅读都围绕同一资料，离开可回来 |
| 搜索结果 | 判断哪条能解决我眼前的问题 | 打开匹配片段 | 进入正确内容类型和段落，不只回到原文 |
| 模型设置 | 配一次自己的服务，以后不用重复处理 | 选服务、填 Key、选用途模型 | 保存后返回正在处理的资料；高级参数不占主要界面 |
| 任务记录 | 必要时了解过去/当前处理情况 | 查看对应资料、继续可恢复操作 | 辅助排查，不是每次正常使用都必须经过的中转站 |
| AI 接入 | 把已经有价值的库交给自己的 AI | 选具体客户端、按步骤接入、验证 | 能实际问 AI 找一条资料并返回来源 |

按钮的验收不是「点了触发接口」，而是用户知道为什么点、点完得到什么、反馈是否符合预期、下一步是否可达。每个空状态/失败状态也要以当前用户的目标承接，不只是告诉用户系统内部缺了什么。

## 用户体验验收标准

1. 新用户不看技术文档、不由开发者口头引导，知道如何保存一条和导入已有收藏。
2. 保存后能明确区分「留下资料」与「得到笔记」，并知道如何继续生成。
3. 需要本人登录或模型配置时，不丢输入和当前资料，不迫使用户重新从头开始。
4. 不到任务页、不懂选帧参数，也能完成正常的保存、整理、阅读过程。
5. 处理完成后能找到总结、转写、画面文字，并复制使用或回看来源。
6. 导航、刷新、离开再回来不会让用户丢失处理位置或误以为任务消失。
7. 能根据实际搜索能力找回内容；无结果时有与搜索问题相关的引导。

前述体验流程应作为整改和验收主线；下面观察到的错误、缺失和实现范围，是实现它的证据与待办，不是对用户体验问题的替代定义。

## 模拟用户与目标

模拟用户：小周，日常会收藏 AI 绘图、视频和开发教程的普通创作者。会复制抖音分享链接，不懂选帧、模型协议、CLI、MCP 配置文件或内部任务状态。

听到宣传后的期待：

1. 今天看到的教程可以保存下来；自己的已有收藏也能导入。
2. 点一次就能得到可阅读的转写、画面文字和总结。
3. 下次记不住标题时，仍能找到相关教程，打开结果、复制使用并回看来源。
4. 可选把资料交给已有的 AI 助手；不需要先懂全部技术才能存第一条资料。

这是代理按上述画像完成的启发式审查，不是真实用户研究，不把模拟的想法当成所有用户的实测结论。

## 实际用户旅程

| 环节 | 小周会怎么想/怎么点 | 实际观察 | 判定 |
| --- | --- | --- | --- |
| 首次打开 | 我先把刚看到的链接贴进去 | 首页有直接粘贴输入和添加按钮，无须先打开弹窗或输入管理口令 | 入口基本明确 |
| 导入已有收藏 | 我不是只想存一条，我想导入抖音收藏 | 空列表给「去同步内容」；进入后有「连接抖音」；尚未连接时不会显示可选喜欢/收藏夹 | 可到达，但首页第二条路径不够明确，宜直接叫「导入我的抖音收藏」 |
| 误粘普通文字 | 我贴错了，哪里错？ | 无链接时提示「一次只接收一个抖音链接」 | 有行内错误，但无链接与多个链接未区分 |
| 添加已有真实链接 | 这条到底存好了吗？ | 出现等待入库，后变「已入库」，有「查看内容」「查看任务」；增加单条链接关系但唯一作品仍为 9 条 | 保存和去重可用；没有提示接下来提取，且掩盖准备阻塞 |
| 打开保存的内容 | 为什么还是抖音的介绍，没有视频里的内容？ | 默认显示已有原文，列出转写/画面/总结尚未提取 | 没假装存在总结，但平台说明被当作长标题并在正文重复，容易误解为已解析正文 |
| 点提取内容 | 那我点提取就好了 | 真实已下载作品的弹窗提示「尚未保存原媒体，请同步时启用保存视频/图片」；仅能关闭 | 核心阻断：把准备失败误报成未下载，无可执行的下一步 |
| 打开转写 | 在这里生成或者继续处理不就好了？ | 未提取显示红色缺失提示；本区没有就地继续处理或解决原因的按钮 | 空状态没有接下一环，用户必须自己猜回上方找提取 |
| 查看任务/批量提取 | 也许任务页可以继续 | 链接任务显示「已完成」，详情只有保存作品；批量提取提示无可提取媒体并让用户保存原媒体 | 同一阻塞再次出现；不是用户没找对入口 |
| 查看已有成果 | 生成后在哪里看？ | 人工样例有总结时默认展示总结；「转写」「画面文字」页签能显示对应正文 | 阅读入口存在；结论仅针对样例渲染，不代表真实提取已通过 |
| 复制复用 | 我想把转写或总结拿去用 | 有来源链接复制；正文没有直接复制按钮；总结以原始 Markdown 文本呈现 | 可手动选择，但缺少简单复用操作与正常阅读排版 |
| 查找资料 | 我记得那条讲角色三视图 | 搜索仅在样例总结中的「角色三视图」能返回一条，说明正文可被索引 | 关键词搜索可用 |
| 记不清标题再找 | 怎么让不同视频里的主角长得一样？ | 同一样例未命中；无结果页面给「去同步内容」 | 一次同义描述测试未命中；错误引导不区分空库与搜索没命中，不能据此宣传任意自然描述都能找回 |
| 清除搜索 | 我回首页继续看全部 | 列表查询清掉了，顶部搜索框还留着旧文本 | 两个搜索框没有统一状态，会造成范围误解 |
| 配置模型 | 为什么需要 Key，在哪里拿？ | 模型服务按预设供应商选择，再填 Key；地址在预设模式无需填写，高级设置折叠 | 形式已比技术参数堆叠明确；缺少与提取阻塞直接相连的配置入口和配好后返回原资料的衔接 |
| 自动处理 | 我以为保存后会自动总结 | 默认自动提取关闭；选项在设置的处理页，写明只处理启用后的新内容 | 不自动收费合理；保存结果应明确当前是仅保存还是自动提取，而非让用户自己找全局开关 |
| 交给已有 AI | 我用哪个软件？配置放哪里？ | 默认给 MCP JSON，说明粘到 AI 工具 MCP 配置；HTTP 在选择项内，CLI 折叠 | 对熟悉 MCP 的用户能用；缺少具体客户端的逐步接入与连接验证，小白接入未通过 |

## 优先修复清单

### P0：先让实际内容处理可以继续

1. **媒体准备恢复由系统承担。** 现有样本选帧触及上限，必须提供能处理常见长/动态视频的有界策略与分段路径；不能要求普通用户自行分视频、调采样参数。保留原媒体并复用，别通过反复下载解决准备失败。
2. **统一真实状态。** 未下载、下载失败、已下载待准备、准备失败、待提取、提取中、结果完成分别返回。详情和任务不能把准备失败解释为没下载。入库成功只能表示保存成功，不表示转写/总结已完成。
3. **保存后有可执行下一步。** 显示「已保存」及「生成转写和总结」；未就绪则直接对应「继续准备/重试下载/配置模型」。配置后回到同一条资料，不让用户重新粘链接。
4. **当前测试版云执行未开启应单独处理。** 这是测试启动条件，不把它和选帧失败混为一个原因，也不把禁用执行的版本称为可完整体验版。付费请求仍按已有授权范围验证，不扩大批量。

### P1：把结果阅读与找回接顺

5. 详情清楚展示「总结 / 转写 / 画面文字 / 原文」，有结果优先展示；没有结果就地显示准确状态和主操作。选择资料后收起大型添加区，让阅读成为当前焦点。
6. 正文正常渲染，提供复制正文、复制带来源内容。平台长描述不能整段占据大标题；完整来源文字仍保留。
7. 保存/提取进度跨导航和刷新保留，不能只存在首页组件的临时状态里。当前添加记录离开首页后消失，用户只好另找任务页。
8. 搜索结果展示命中摘要和命中的内容类型；无结果给清除条件、换关键词/同义提示与扩大范围。空库才给导入引导；两个搜索框和地址状态保持一致。
9. 任务显示来源名、作品、时间、完成项、失败项和继续入口。不能一列同名「来源同步」让用户猜哪个是喜欢、哪个是收藏夹。
10. AI 接入按具体客户端给安装位置与验证步骤。自然语言检索先明确由宿主 AI 改写/拆分查询，不为了修体验另建一套聊天大模型或数据库。

## 最小正确流程与下一次开发验收

首页两条明确路径：**粘贴一个链接** / **导入我的抖音收藏**。

正常路径：

`保存链接或同步 → 明确已保存 → 生成转写和总结（或明确选择自动处理） → 原处看进度 → 原处查看结果 → 复制/回看来源 → 下次搜索找回`

受阻路径：

`当前资料显示具体原因 → 唯一对应的处理入口 → 完成必要设置/重试 → 返回同一资料继续`

这不要求重写两个客户端，不增加企业级后台。使用现有统一后端和已有组件把状态与操作补完整。

开发方自行验收应包括：正常短视频、现有长/动态视频、未登录、未配模型、只保存文字、下载失败、准备失败、模型失败、已有结果、重复链接、导航/刷新后继续、关键词命中和无结果引导。真实云质量只能在获准调用后单独验证，不能用人工样例或接口测试代替。
