# 统一后端：固定配置与重启续跑验证

日期：2026-10-01。自主重写的开发切片；完整 MVP、真实平台连接、云模型质量与三端发行仍未验收。

## 1. 本批实现

之前已有内部阶段执行器，但调用者重启后需要自己重建同一组阶段对象。本批增加：

- `processing/inputs.py`：独立输入登记。原视频/有序原图、准备后的音频段与画面均按哈希保留，清单版本化、原子提交、受控路径读取。临时解码路径不写入任务；重复登记复用相同快照，孤立的未提交清单不能冒充已登记输入。
- `processing/profiles.py`：三角色配置及不可变快照。默认角色绑定可以更新，已排队任务固定旧地址、模型、协议、参数、凭据引用与策略。配置版本/哈希不符时拒绝执行，不自动改用当前默认值。
- `infrastructure/secrets.py`：显式独立服务凭据目录，仅当前运行用户可访问。模型 Key 不进任务、库提交、公开配置或测试报告；不读取旧 `.env`、第三方账户或现有 Keychain。
- `workflows/extraction.py`：只根据本项目注册的输入/模型结构重建自有阶段，复用原持久执行器。没有从 JSON 运行 Python、命令、文件导入或任意处理函数。
- 原始图文页有自己的页序号，不使用视频时间戳标注。图文和经媒体探测确认的无音轨视频显示音频“不适用”；未取得音频且未确认无音轨时拒绝这样标记。
- 媒体快照变化也会让机器产物过期，即便标题/正文未变；用户备注保留。旧任务启动前与最终提交时检查媒体版本；云请求期间输入被更新，已确认结果/用量保留，但不能覆盖新资料。

新代码仍在 `backend/src/collection_context/`；没有将外部项目 CLI/后台/账户目录接为运行依赖。旧生产资料、服务、路由与真实凭据没有改动。

## 2. 数据与费用边界

```text
资料库                         独立服务凭据目录（库外）
  ├─ 原始媒体 / 音频 / 原图       └─ k_...：私有权限文件
  ├─ 输入清单 u_...                         ↑ 仅执行时解析
  ├─ 非秘密配置快照 p_... + 凭据引用 ───────┘
  └─ 任务：固定输入ID、角色快照ID、策略、调用上限
             ↓ 新进程重建自有阶段
        检查快照和权限 → 派发已授权请求 → 确认结果/用量 → 原子产物
```

- 提交任务不解析模型秘密、不发请求，也不隐式开启自动处理。实际执行由独立命令明确启动；默认三个只读 MCP/HTTP 工具仍无写入或付费权。
- 调用上限是请求次数，不是金额或 Token 上限；没有价格配置时不能给准确费用估算。执行会把音频、画面及汇总证据发送到指定模型接口，不能宣传全程离线。
- 配置新模型/Key 只改变新任务的默认绑定；旧任务所需凭据缺失时明确报错，不能从其他项目或全局环境找一个 Key 代替。密钥轮换/任务显式重新绑定界面仍待实现。
- 文件凭据后端是**权限受限的明文服务文件，不是加密钥匙串**，适合显式受保护的服务配置。桌面系统凭据库和 Windows 安全适配仍待验证；当前不得把它称为三端默认方案。
- 库与服务凭据目录不允许重叠。完整备份/导出还待实现；恢复库时凭据需单独配置，不应复制这批开发测试的私有凭据目录。
- 当前登记上限：原媒体单份128MB、总快照512MB、240原图/选帧、64音频段；单个模型输入另受32MB上限。超限报错，不裁掉后面的页面/音轨。原始视频默认保留，未增加自动删除或垃圾清理。

## 3. 新的本地开发命令

以下只用于新后端工作目录、已经登记的资料和明确媒体文件。自有平台添加/登录尚未接通，不能在空库中随便编一个资料引用，不能对现有私人库运行初始化。轻量页面的连接、模型配置和处理按钮仍禁用，没有把 CLI 能力冒充前端完成。

| 命令 | 实际作用 | 模型请求 |
| --- | --- | --- |
| `model-settings` | 读取默认三角色的非密钥配置，秘密引用也不回显 | 0 |
| `configure-model` | 配置角色；已有独立凭据引用，或交互终端无回显输入 Key | 0 |
| `prepare-video` | 固定 FFmpeg 准备、保存原视频和提取输入 | 0 |
| `prepare-images` | 按完整顺序登记原图及页编号 | 0 |
| `submit-extraction` | 固定输入/角色/预算和幂等键，返回 queued 任务 | 0 |
| `run-job` | 显式执行一个已提交任务，重建/复用自有阶段 | 可能计费，按已固定调用上限 |
| `job-status` | 只查看本地拥有者任务 | 0 |

全局参数均为 `collection-context --workspace <新产品工作目录> <命令> ...`。输入和任务引用使用上一步返回值。例：

```text
collection-context --workspace <工作目录> model-settings
collection-context --workspace <工作目录> configure-model --role audio --base-url <接口地址> --model <音频模型ID> --protocol chat_audio --prompt-key --credential-dir <库外私有目录>
collection-context --workspace <工作目录> prepare-video --ref <已有资料ID> --input <明确视频文件>
collection-context --workspace <工作目录> prepare-images --ref <已有图文ID> --image <第1张图> --image <第2张图>
collection-context --workspace <工作目录> submit-extraction --input-id <返回的输入ID> --idempotency-key <本次请求稳定标识> --max-calls <明确请求次数上限>
collection-context --workspace <工作目录> run-job --job-id <返回的任务ID> --credential-dir <库外私有目录>
collection-context --workspace <工作目录> job-status --job-id <返回的任务ID>
```

`--prompt-key` 仅接受交互终端；不提供 `--api-key` 参数，也不从聊天收集 Key。音频支持已实现的 `chat_audio` 或 `transcription`，图像和总结使用 `chat`；三个角色可以指定不同模型。能力的真实支持度仍要用小样本另验，设置成功不等于模型能识别。

`run-job` 是本地显式前台执行命令；对外异步任务入口/后台服务未开放。CLI 提交与执行分离并不代表自动调度已实现。前置输入/凭据错误会拒绝执行且无调用；当前任务管理界面和显式排障再排队还待接线。
