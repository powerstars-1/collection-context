# 收藏上下文：管理界面逐功能、逐按钮整改规划

日期：2026-10-03。状态：仅规划，待用户确认；本轮不继续改业务代码。

本文是[开发总计划](2026-10-01-抖音上下文MVP-开发规划与分阶段验收.md)中 R10 管理界面的整改细则，同时覆盖 R01～R09、R13 的界面入口。不另建产品、不更换前端框架、不重写已经认可的 Creator 组件外观。

## 1. 这次改什么

当前界面把后台的验证、登记、预览、执行限制直接交给用户操作，导致用户需要理解内部机制才能完成一件事。这是产品设计问题，不是用户看不懂。

整改目标：用户知道自己要做什么，点相应按钮，看到结果。设置用来配置，说明放到帮助；后台承担计算、校验和流程衔接。

本规划依据当前 `frontend/src/` 实际按钮、表单和事件处理核对。它不是已经实现或已经通过真实页面验收的声明。当前页签有过滤处理，但标题和空态缺少区别，不能简单把问题说成“所有点击没有接线”。

### 页面固定为四个入口

| 顶部入口 | 左侧入口 | 主要内容 |
| --- | --- | --- |
| 收藏库 | 全部、喜欢、收藏、收藏夹、博主作品、单条链接 | 找资料、看内容、看来源 |
| 同步 | 来源、任务 | 连接抖音、选择来源、手动同步、查看进度 |
| 设置 | 模型服务、处理设置、数据与存储 | 配一次服务、分配模型、自动处理、查看用量与空间 |
| AI 接入 | 不再放只有一项的左侧菜单 | 选自己的 AI 工具，复制对应配置 |

默认主界面不出现协议、JSON、配置版本、证明有效期、内部任务 ID、调用次数计算公式、执行器所有权、英文阶段名。

### 三条日常路径

1. 第一次：连接抖音 → 选来源 → 同步 5 条 → 在收藏库看到资料。
2. 提取：设置模型 → 保存 → 在资料或任务页点击“提取内容” → 看转写、画面文字、总结。
3. 后续：手动“立即同步”，或打开自动同步 / 新内容自动提取 → 随时到收藏库检索。

自动同步和自动提取是两个独立开关。保存模型不启动提取；打开新内容自动提取不补跑全部历史。

## 2. 所有按钮共用的规则

- 一张卡片或一个弹窗只保留一个主操作；其他操作用次按钮或“更多”。
- 普通保存、搜索、刷新不要求勾选长篇确认。上传到云模型、开启自动提取、重新计费、移除来源等在对应动作时一次确认。
- 点击后立即显示“连接中 / 同步中 / 保存中 / 提取中”，并阻止重复提交。
- 成功必须刷新相关列表、数量和状态；不能只出现一句“已登记”。
- 失败就在发生操作的位置显示一句原因和一个下一步，例如“登录已失效 · 重新登录”。完整错误收进“查看详情”。
- 禁用按钮必须在附近显示原因和可操作入口，不能只有灰色。
- 空列表区分“确实没有”“尚未同步”“加载失败”；失败不能伪装成零条。
- 返回、刷新、切页后保留筛选和正在执行的任务；不自动重弹登录窗口，不丢进度。
- 页面自动更新只读取状态，不自动重试平台访问或付费请求。
- 现有后台去重、范围限制、任务检查点继续保留；不把这些内部概念做成用户必须学习的步骤。

## 5. 同步：把一次动作接成完整流程

### 5.1 抖音连接与来源选择

| 编号 | 当前按钮/控件 | 整改后 | 点击后必须发生什么 |
| --- | --- | --- | --- |
| S01 | 打开独立登录 | 改“连接抖音”；已失效时“重新登录” | 只开一个登录窗口；登录完成后回主页面显示账号和收藏夹列表 |
| S02 | 验证已有登录 | 从主界面移除，合并到连接流程 | 后台完成必要检查；用户不分别点登录与验证 |
| S03 | 发现收藏夹 | 合并到首次连接；已连接后为次按钮“刷新收藏夹” | 把名称列表带回当前页面；明确“没有收藏夹”或“获取失败”，不只弹页面又关闭 |
| S04 | 刷新本地连接 | 从主界面移除 | 页面自动读本地状态；故障详情中保留“重新检查” |
| S05 | 允许本次独立浏览器访问勾选 | 合并到“连接抖音”的明确操作 | 不要求用户点三个动作前分别勾选同一段文字 |
| S06 | 取消本次验证 | 运行时显示“取消连接” | 停止本次流程，保留此前有效连接；主页面显示已取消 |
| S07 | 选择本人列表下拉 | 改“喜欢 / 收藏”独立选择项 | 可同时选择两类来源，不反复保存两张同样的表单 |
| S08 | 已观察收藏夹下拉 | 改名称列表，可多选 | 显示名称，不把 ID 拼在每项后面；同名夹必要时以少量附加信息区分 |
| S09 | 三处每批最多作品数 | 统一“每次同步数量” | 5 / 10 / 20 与自定义，首次默认 5；本轮不扩大后台已允许范围 |
| S10 | 各下载并准备媒体勾选 | 合并“同时保存原视频/图片”开关 | 一次选择，清楚控制本次来源配置；关闭时资料标为尚未下载 |
| S11 | 本人/收藏夹范围确认勾选 | 取消重复勾选，保存前显示范围摘要 | 摘要列出来源名和数量，“保存并同步”就是这次授权 |
| S12 | 保存本人范围 | 合并“保存并同步” | 保存选择并立即创建一次可执行同步；实时显示数量和结果 |
| S13 | 保存收藏夹范围 | 合并同一个“保存并同步” | 所选夹分别保持归属；同作品不重复保存 |
| S14 | 新增“只保存设置”次按钮 | 与保存并同步并列 | 只保存、不运行；反馈“已保存，尚未同步”，不能报同步完成 |
| S15 | 博主完整主页输入 | 改“博主链接或分享文字” | 解析后展示博主名供确认；不能解析则指出链接问题，不要求用户手改短链 |
| S16 | 保存博主范围 | 改“添加并同步” | 加入来源列表并启动该数量作品的同步；提供只添加选项 |

窗口关闭不是连接结果。完成条件是产品页面显示确认过的账号和收藏夹列表；失败条件要在产品页面给原因与重试入口。无桌面服务器不展示一个注定无法弹出的登录按钮，另显示其受支持的登录方式；尚未跑通要明确不可用。

## 6. 任务：只显示进度和处理入口

### Pi SDK 接线明确纳入整改

- **当前事实（整改实现更新）：文字/图像已接入 Pi SDK。** 本机原创 HTTP 流式响应的 3 项 SDK 测试通过；真实云模型质量及跨平台 Node 发行仍为独立验收，不能用本机响应冒充真实模型质量。音频仍使用统一云音频适配入口。
- 文字与图像接入优先复用用户指定的 [Pi AI SDK](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md) 的提供商、模型目录和调用适配。
- Pi 与现有 Python 后台的语言边界在内部处理：使用随产品管理的协议适配进程，不建立另一个用户要启动的服务，不再做第二套客户端。
- 音频按 SDK 实际支持情况走同一后台的音频适配，不能声称使用统一 SDK 就自动支持所有转写模型。
- 前端只接本项目统一模型服务接口，不自己调用上游、不拿 SDK 直接持有 Key；任务、媒体、文件与用量仍由自有统一后台管理。
- 接入交付包含模型列表、文本、图像、错误与用量映射测试以及跨平台打包；不能“装了依赖”就标为已接入。

## 9. 实施顺序和交付门槛

确认后按以下顺序交付，每批必须是能实际点的闭环，不继续堆与眼前体验无关的工程项。

| 批次 | 内容 | 必须拿出的验收结果 |
| --- | --- | --- |
| 1 | 全局导航、收藏库分类与空态，连接抖音 → 收藏夹列表 → 保存并同步 | 真实页签切换有不同标题/数量/结果；连接不反复开窗；同步后可以点开真实资料 |
| 2 | 正常模型服务设置、用途分配、Pi 文字/图像接线和统一音频入口 | 同一 Key 不重复填；重开页面仍保存；模型列表和角色选择正确；有权限的小样本才能实测云调用 |
| 3 | 单条提取 → 可读结果 → 任务重试/取消；自动处理设置 | 用户不需要另开执行器；结果直接出现在详情；失败有明确可用操作，不重跑成功步骤 |
| 4 | 导出/隐藏/恢复、空间用量、按客户端显示 AI 配置 | 文件包可打开；隐藏与恢复实际影响检索；宿主一次搜索/读取返回真实来源 |

开发遵循现有组件结构，不再平行维护一套不同交互的旧管理表单。逐功能替换当前静态管理区和控制器到正常组件，复用已经有效的后台能力；补齐服务级配置与动作接口，不仅换标签。

### 每个按钮的验收单

对本文每个编号记录：实现位置、正常结果、失败结果、重复点击、刷新/返回、实际浏览器证据。移除或合并的按钮记录承接编号。新按钮必须有真实动作，否则不出现。

核心验收数据至少含喜欢、收藏、两个收藏夹、一个博主、一个单链接，且各类有可区分的作品。不能用同一套空库或五条演示资料证明真实分类、来源同步通过。

模型付费验收使用新的明确授权；此前批准的 8 次质量调用已经用完，本规划不追加调用。真实登录由用户自己完成，需要时一次说明卡在哪一步；不要求用户替开发者四处找链接、猜按钮用途。

Mac 当前可测闭环优先交付；Windows/Linux 保持原定支持和各自实测要求，不拿未完成跨平台发布当作不交付 Mac 测试版的理由。旧服务、私人生产库、公开发布不在本次界面整改的自动授权内。

### 完成的判定

用户无需读技术解释，可以完成“配置服务 → 连接抖音 → 选一个收藏夹同步 → 提取一条 → 看总结/转写/画面 → AI 查到原资料”。只有这条真实链路以及对应按钮结果通过，才说该批已完成。自动测试数量不替代这件事。
