# Pi 模型 SDK 接入评估

日期：2026-10-02。状态：已查上游文档和类型、本仓库现行调用；**未安装、未接入、未替换已验证模型链路**。本文是技术评估，不是新的用户决策或已完成声明。

## 结论

可以作为文本／视觉模型的统一协议 SDK 候选，借鉴其供应商工厂、模型能力、思考参数和用量事件分层。它不接管我们自己的来源同步、媒体准备、任务、权限、预算、证据引用或凭据管理。当前 Python 独立后端不能直接 import 这个 TypeScript 包；增加 Node 子进程或改模型工作进程要重新验证三端发行和收费边界，不在本次复查中擅自迁移。

## 实际核查

- [上游 README](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md)描述统一 LLM 调用、图像输入、供应商工厂、自定义 OpenAI 兼容端点、用量及思考参数。各供应商可独立导入；不必载入全部目录。模型目录包含小米和千问 Plan，但目录存在不能证明本用户订阅权益、实际端点或模型能力。
- [package.json](https://github.com/earendil-works/pi/blob/main/packages/ai/package.json)当前 main 写明 ESM、Node >=22.19.0、MIT，并依赖多个供应商 SDK。这是源代码快照，不是已验证 npm 发布版本、三端打包体积或完整传递许可审查。
- [公开类型](https://github.com/earendil-works/pi/blob/main/packages/ai/src/types.ts)的 UserMessage 输入为文字或文字／图片数组，未提供我们的 WAV／MP3 chat_audio、multipart transcription 对应统一输入。价格结构出现 audio 项不能证明音频调用已实现。请求选项有 maxRetries／timeoutMs／signal，需要逐一验证供应商实际遵守；不能假定“统一选项存在”意味着每个协议都执行相同限制。

## 与本产品的边界

本仓库 `backend/src/collection_context/processing/models.py` 已统一三种协议：chat、chat_audio、transcription；不是每家供应商各写一个后台。现有执行者先持久登记调用意图，再发请求，未知结果禁止自动重发，保留实际模型／上游请求 ID／返回用量，未返回的缓存或费用不填零。这些行为不能因换 SDK 消失。

若进入接入实施，优先只替换文字和图像的传输层，音频保留独立适配；统一结果仍回到现行 ModelResult 和持久阶段。端点和 Key 必须显式传入，不自动读其他应用账户、环境凭据、CLI 配置或 OAuth 登录。SDK 目录仅作建议，不自动覆盖用户固定模型。金额估算须与上游返回实测分开。

选择前必须做离线契约验证：调用次数严格一、maxRetries=0、超时／取消后的未知用量、跨站重定向不带 Key、截断及空输出、响应体上限、用量缺失／缓存未知、失败脱敏、正确地区／自定义网关。随后才在已有授权上限内进行实际模型验收；本次没有新增模型请求。

推荐保留可替换的统一调用边界，而不是另开一套服务或把宿主 Agent 搬进项目。是否接受 Node 运行依赖及供应商扩展范围，须明确后再迁移；这一选型不阻止当前三端原生适配开发，也不算现行 MVP 已接入 Pi。
