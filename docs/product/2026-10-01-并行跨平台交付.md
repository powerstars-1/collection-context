# 并行跨平台交付：安全文件与所有权门禁

日期：2026-10-01。状态：**macOS arm64 原生专项通过；Windows 适配未实现且仍禁用；Linux 需分架构原生复验。**

本交付只处理 `collection_context.infrastructure` 的受控文件访问、内核所有权与目标机验收入口。没有连接私人资料库、平台账号或模型，没有改变生产服务。

## 1. 实际修复

`SafeFiles.write(..., replace=False)` 原先会先在最终文件名上创建空文件，再写入和刷盘。如果中途失败，读者可能看到半成品或遗留的目标文件。现改为：

1. 在相同目录的随机临时名写完并 `fsync`；
2. 发布前重新核对资料库根身份；
3. 首次发布使用同目录硬链接实现原子且不覆盖的命名，随后立即去掉临时名；
4. 覆盖仍使用同目录 `os.replace`；
5. 任意失败路径尝试清理未发布临时文件。

读取版本核对也从“大小 + 修改时间”扩展为设备、inode、文件类型、链接数、大小、mtime 和 ctime。读取期间新增硬链接会以 `version_changed` 停止，不把已变化的文件当作稳定证据。

## 2. 能力检测和失败边界

`platform_safety.detect_platform_safety()` 只检查当前真实解释器，不接受伪造的平台名参数。当前已启用的后端为：

- `posix_dirfd_v1`：要求目录描述符相对操作、`O_NOFOLLOW` 等能力；
- `posix_flock_v1`：要求 `fcntl.flock` 和读取已打开描述符的能力。

能力不足时返回 `unsupported_platform`，不降级为普通字符串路径读取，也不根据 PID、时间或遗留文件猜测任务已死后接管。Windows 需要能等价固定目录身份、拒绝重解析点/硬链接、防读中替换并提供跨进程内核锁的独立适配；在此之前不启用 Windows 读写。

## 3. 目标机验收入口

在每个真实目标系统和目标文件系统上运行：

```bash
PYTHONPATH=backend/src python -m collection_context.infrastructure.platform_acceptance
```

如需验证外置盘或另一个本地文件系统，可指定已存在的父目录；工具只在其下创建并清理随机临时目录：

```bash
PYTHONPATH=backend/src python -m collection_context.infrastructure.platform_acceptance --parent "/path/to/volume"
```

工具没有 `--platform` 覆盖。报告内嵌真实系统、内核版本、CPU 架构和 Python 版本，验证：

- 中文和空格路径的首次发布、不覆盖冲突及原子覆盖；
- 符号链接和硬链接读取拒绝；
- 根路径被替换/外置盘身份变化后停止写入；
- 真实子进程持锁时第二写者被拒绝，子进程退出后可重新取得所有权；
- 所有权文件被替换后停止提交。

退出码 `0` 仅表示报告所列当前主机的这组临时文件系统专项通过；`1` 表示专项失败；`2` 表示没有合格适配。报告固定包含 `release_support_claim: false` 和 `full_product_regression: false`，不能单独用于宣布系统发行支持。

## 5. 后续门禁与回滚

Windows 后续实现不能删除 Unix 检查或共用字符串路径逻辑。应先提交独立后端，再在真实 Windows x64 普通用户环境运行本工具、专项测试和完整产品回归。Linux x64 与 Linux ARM64 也分别出报告，不共用架构结论。

本交付没有资料迁移或格式升级。若回滚代码，可对本分支交付提交执行 `git revert <commit>`；无需改动现有资料库。
