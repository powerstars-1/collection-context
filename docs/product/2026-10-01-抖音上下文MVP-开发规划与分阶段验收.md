## 1. 产品目标、范围与完成定义

### 1.1 用户获得什么

一个用户自己运行的工具，把抖音中喜欢、收藏、指定收藏夹及指定博主的内容，保存为可读、可查、可追溯的资料。用户自己的 AI 能找到过去的教程，引用原文、口播和画面证据，也能按用户要求分析兴趣线索。

不要求安装 Obsidian、New API、WeKnora 或多个第三方桌面应用。用户可直接阅读 Markdown；界面、CLI、MCP/API 共用一个后台。项目不提供模型账户或推理云服务。

### 1.2 首发需求清单

| 编号 | 必须交付 | 边界 | 主要验收阶段 |
| --- | --- | --- | --- |

| R02 | 收藏及指定收藏夹同步 | 分别标记收藏关系、夹内归属和实际同步覆盖 | G1、G4、G6 |

首版单账号、单用户、一个进程组管理一个资料库。不做评论、多账号切换/多租户、自动个人画像、内容发布、财务整合、独立聊天机器人、插件市场。PDF/Word/其他内容平台、向量检索和原生整段视频理解不作为首版新增必交付功能；旧内部能力保留。

完成定义：普通用户从干净安装到一次带来源的 AI 回答跑通，五类入口逐项验收，三端及 Linux 无桌面路径均有证据。某类同步缺失时应标明候选版缺口，不能未经用户同意把“只有单链接”改称原定 MVP 已完成。

## 2. 用户流程与三个页面

### 2.1 第一次安装

1. 下载本系统安装包，打开轻量启动器；显示后台状态并打开浏览器管理页，无需手工配 Python/Node。
2. 选择新库或连接旧库：新库要求空目录；旧库先只读识别，不复制或迁移原目录。库初始化不登录平台、不同步、不调用模型。
3. 用内置原创样例展示搜索、转写、画面证据与来源；不登录也能体验读库。
4. 用户主动连接抖音，完成登录，选择喜欢/收藏/收藏夹/博主。登录方式由技术验证确定，不预先承诺某种扫码接口。
5. 填模型接口地址、API Key、模型名，分配音频/图像/文本角色；可用同一个已验证的多模态模型。测试按钮注明会上传的小样本和可能费用。
6. 查看首次同步与处理数量，先小批试跑；查看转写、关键帧和总结是否符合预期。
7. 用户选择自动处理新增内容或保持手动，确认预算/数量限制；历史补处理保持独立。
8. 选择 AI 接入方式，预览权限、完成实际调用；显示测试结果及可复制的示例问题。写好配置文件不算接入成功。

### 2.2 日常使用

同步已选来源 → 保存内容及来源关系 → 判断是否已有有效提取 → 根据自动开关进入任务或等待手动 → 音频/画面处理 → 总结与文件提交 → 更新可检索内容 → 用户的 AI 按需读取。

每天不自动重复总结整库，也不自动生成一份个人画像。用户可问“最近喜欢什么类型的教程”，但系统返回必须保留观察时间和覆盖限制，详见第 5 节。

### 2.3 页面职责

| 页面 | 用户能做什么 | 必须看得见的反馈 |
| --- | --- | --- |
| 我的资料（界面名称暂定） | 搜索；按喜欢/收藏/收藏夹/博主筛选；看原文、转写、画面、总结；打开来源；排除或导出 | 多来源标签、证据类型、缺失项、来源与时间含义；有总结也可直接读完整提取 |
| 添加与连接 | 粘贴链接；登录/退出；选收藏夹；增减指定博主；连接 AI | 登录状态、实际同步范围、已授权权限、尚未验证的客户端提示 |
| 处理与设置 | 自动开关；手动/历史任务；取消/定点重试；模型、空间、用量、备份和诊断 | 当前阶段、已完成项、下一步、请求次数/用量/未知费用、待用户处理的原因 |

资料详情是第一页内的详情视图；不用另造完整创作工作台。错误用用户可执行的下一步表达，原始堆栈和平台响应不直接展示。常见操作可用键盘，状态不只依赖颜色，窄屏可查看和处理异常。

### 2.4 无桌面服务器

用户部署同一后台，指定数据目录与受限凭据；无需 Mac 或桌面应用。管理页可由另一台设备在受保护的连接上打开。同机 AI 用 CLI/stdio MCP；异机用认证 API，或客户端适配所需的远程 MCP。

平台登录、验证码和续期独立验收：服务器可由用户在手机/浏览器参与验证，但必须是平台允许、实际可用的路径。遇到无法无桌面完成的验证要暂停并说明；不能偷偷使用用户 Mac 的现有登录库，也不能因为后端能启动就宣称服务器同步通过。

## 3. 默认行为与配置决策表

以下为**建议工程默认值，随本规划一并评审**；数量/性能阈值可在技术验证后调整并记录，不改变已确认功能范围。

| 配置 | 建议默认 | 规则 |
| --- | --- | --- |
| 同步范围 | 首次由用户选择，不预选全部 | 收藏夹和博主有稳定范围 ID；名字只用于显示 |
| 首次样例/试跑 | 每批最多 5 条 | 先展示范围再执行；样例本身无需云调用 |
| 自动同步 | 初始化关闭；向导中可启用 | 与自动提取分开；启用后建议每 60 分钟，按平台约束降低频率 |
| 新增内容自动提取 | 初始化关闭；配置模型并确认发送内容后可开启 | 用户可随时切换；开启时记录切换边界，不自动吞掉所有历史待处理 |
| 历史补处理 | 手动选范围，建议每批 20 条 | 显示数量/媒体时长/待识别帧上限；每批独立可取消 |
| 任务并发 | 一个媒体处理任务；最多两个云请求并行 | 音频与画面可独立推进；一个预算管理器统一预占名额 |
| 单视频画面上限 | 暂沿用 240 张作为保护上限 | 超出暂停，提示分段或显式调高；不静默删帧后称完整 |
| 已发出模型请求的自动重试 | 默认不自动重复 | 明确失败/结果不明分别记录，手动重试提示可能重复收费 |
| 原视频 | 保留 | 后续可显式启用“完整提取成功后清理”；提供预览和空间提示 |
| 文字、来源、关键帧 | 长期保留 | 用户主动删除/排除另走数据管理流程 |
| AI 权限 | 只读 | 添加链接单独授权；同步计划、模型配置、删除不默认暴露给 AI |

自动开关关闭后停止后续自动调度。已发出请求可继续产生费用；界面显示仍在运行的项，不保证撤回或退款。暂停同步、关闭提取和取消当前任务是三个不同操作。

未配云模型时仍可保存元数据和允许下载的附件，显示待提取。缺音轨可标“不适用”；有音轨但没配模型只能标“未转写”。休眠恢复或停机后只接续检查点，不补跑所有错过的定时次数。

## 4. 统一后端与工程布局

### 4.1 四个模块的输入输出

原创实现约束：来源连接、同步、转写接入、处理编排和资料管理由本项目独立实现。参考项目用于理解协议、字段和失败情况，不作为用户必须安装的运行服务，也不通过调用其 CLI 拼接产品。尤其音频转写由自有代码完成分段、模型协议适配、结果归一、用量记录及恢复；识别推理由用户配置的云模型提供。FFmpeg、OCR 推理库和协议 SDK 等通用依赖可按许可使用；实际借用源代码须保留来源与版权，不能将改名包装视为原创重写。

用户再次提醒后固定为验收门槛：新环境仅安装本产品及声明的通用依赖即可运行；参考项目的安装路径、运行服务、登录目录及转写命令不进入产品必需链路。旧内部流程可暂时保留，不能把旧流程的成功当作新版通过。开发进度继续推进，重构方向不退回多项目编排包装；每阶段分别提供独立接线与真实效果证据。

| 模块 | 输入 | 输出 | 不负责 |
| --- | --- | --- | --- |
| 来源 `sources` | 已授权连接、来源范围、游标、链接 | 标准内容、附件描述、来源关系、分页与覆盖信息 | 总结、画像、自动付费 |
| 处理 `processing` | 已保存媒体、处理策略、模型角色、调用额度 | 转写、画面文字、总结、证据位置及质量缺口 | 平台登录、用户提问回答 |
| 资料库 `library` | 内容/关系/产物及版本 | 稳定引用、文件、索引、受控检索读取 | 启动同步、重试模型 |
| 流程 `workflows` | 用户或已授权计划提交的任务 | 阶段执行、检查点、预算、取消/恢复、任务状态 | 平台字段解析、具体识别算法 |

应用服务统一参数校验、权限与返回契约。UI/CLI/MCP/HTTP 是薄入口，不分别实现一套业务。媒体工具与浏览器是受控子进程，首版不引入微服务、Redis/Celery、向量数据库或独立文档服务。

### 4.2 技术基线与待验证候选

| 层 | 计划 | 验证重点 |
| --- | --- | --- |
| 核心 | 延续 Python；当前项目要求 Python >= 3.12，发行时锁定实际验证版本 | 新代码有类型和边界，核心不导入桌面或平台专属组件 |
| API | 单一 ASGI 服务；FastAPI 作为拟选适配层 | 不让框架承担任务持久化；错误、权限、关闭恢复可测 |
| 页面 | 后台提供 HTML/CSS 与少量浏览器脚本 | 无独立前端运行服务，终端用户无需 Node；先做流程再视觉打磨 |
| MCP/CLI | 复用现有协议 SDK 与命令经验 | 统一用例和错误；保留旧只读工具名与兼容适配 |
| 媒体 | FFmpeg；RapidOCR + ONNX Runtime CPU 作为 OCR 候选 | 权重、原生库、安装体积、CPU 耗时、漏选情况 |
| 来源连接 | 自有抖音适配器；如需浏览器则验证 Playwright/Chromium | 独立登录、真实来源语义、分页、桌面和无桌面行为 |
| 桌面发行 | 薄启动器打开浏览器；PyInstaller 目录式打包作为候选 | 分系统构建、原生依赖和升级卸载；不默认引入 Electron |
| Linux 服务 | 同一 Python 包/可执行入口；可选 OCI 容器封装 | 无显示服务/GPU，卷持久化、非 root 运行、信号退出和恢复 |
| 存储 | Markdown/附件 + 有版本 JSON 清单 + 可重建索引 | 单写、原子提交、故障恢复；不自行发展成复杂数据库 |

这些是供评审和验证的工程选择，不是本轮安装清单。FastAPI 的后台辅助机制不能替代本项目的持久任务记录；长任务交由自身执行器并持久化检查点。[官方后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)。

若采用 Playwright，浏览器二进制及系统依赖必须一并管理，升级也要重新验收，不能把“安装 Python 包”当作浏览器已可用。[官方浏览器依赖说明](https://playwright.dev/python/docs/browsers)。

若采用 PyInstaller，按目标系统分别构建；Linux 原生系统库也须验证，不能把 Mac 打出的包直接当 Windows/Linux 发行物。[官方打包说明](https://pyinstaller.org/en/stable/operating-mode.html)。

### 4.3 目标代码组织与旧代码过渡

```text
backend/src/collection_context/
  application/       用例、权限、公开契约
  sources/           来源标准化与抖音连接器
  processing/        音频、选帧、视觉、总结阶段
  library/           条目、关系、产物、索引与受控读取
  workflows/         任务、预算、检查点与恢复
  infrastructure/    媒体/模型/凭据/浏览器/安全文件适配
  interfaces/        HTTP、MCP、CLI、页面与启动器
backend/tests/       单元、契约、回归、故障、打包验收
examples/            原创或获授权样例及无密钥配置
docs/                产品、用户指南、开发规范、验收记录
```

这是目标布局，不先批量移动目录。复用 `collection_context_service.py` 的查询与安全测试，拆分 `media_extraction_service.py` 的阶段，保留有效素材输出约定。旧生产 `app` 通过兼容边界逐步接入；新发行包使用明确白名单，不把旧内容生产、私人库和第三方工作副本一起打包。

既有 `douyin-user-favorites` 命令名不能直接当作“本人喜欢”实现证据；当前说明仍称其使用外部项目的用户收藏命令。新连接器须对照真实列表验证喜欢、收藏和发布作品，不按英文方法名猜语义。

### 4.4 现有实现怎样进入新产品

用户再次强调：转写及接入部分要自主重写，原项目用于借鉴输入输出和实现经验；不把其 CLI、后台、账户目录或核心代码整包作为新产品运行依赖。新同步、音频/视觉 HTTP 适配、阶段编排和状态管理均在自有统一后端实现。通用协议 SDK、FFmpeg、OCR 推理引擎按许可正常使用，不要求重新实现通用模型或解码器。

以下为 2026-10-01 只读代码核对后的开发分工，不代表本轮完成改造或重新运行测试。

## 5. 数据模型、来源与偏好线索

### 5.1 最小契约

所有持久结构具有 `schema_version`；时间按带时区格式存储，展示按用户时区。字段未知为 `null` 并说明原因，不使用 0 或空串假装准确事实。

| 对象 | 必需概念字段 | 不变量 |
| --- | --- | --- |
| `Workspace` | 库 ID、版本、根目录映射、布局、创建时间 | 根目录身份可验证；已有非空库不得当新库初始化 |
| `SourceConnection` | 连接 ID、平台、账号受控引用、登录状态、凭据引用 | 秘密不进入库；首版只启用一个账号 |
| `SyncScope` | 范围 ID、类型、收藏夹/博主引用、启用状态、范围上限、检查点 | 范围改动创建新版本，不能沿用不同范围的“全量完成” |
| `Item` | 不透明长期 ID、平台作品 ID、规范来源、作者、标题、正文、媒体类型、发布时间、内容版本/哈希 | 同平台作品去重，身份不依赖标题或路径；视频和图文均有表示 |
| `SourceRelation` | 关系 ID、条目 ID、来源种类、范围 ID、首次发现/最近观察、可选真实操作时间及依据 | 同作品可有多关系；博主作品关系不等于本人点赞 |
| `Artifact` | 条目 ID、类型、相对路径、哈希/版本、输入版本、处理器/模型/提示词版本、状态、覆盖/缺口 | 原文、ASR、画面、摘要和用户备注分开；摘要有输入证据引用 |
| `Job` | 任务 ID、类型、幂等键、目标范围/条目、策略版本、阶段、检查点、预算/用量、错误 | 运行状态不从正文猜；重启能识别未完成阶段 |
| `ModelResult` | 内容、实际模型、用量、上游请求标识、耗时、结果状态 | 未返回用量不得伪造；不在原始正文中解析一个数字当账单 |
| `Coverage` | 范围、观察时间、处理条数、游标、是否完整、停止原因 | “最新 N 条”“指定时间段”“全范围”分别描述 |

公共接口只返回受控引用和必要业务字段；账号、私有原始返回及内部绝对路径不默认暴露。引用不是权限凭证，每次读取仍重新检查范围。

### 5.2 多来源去重示例

同一作品先被发现于喜欢列表，后来放进两个收藏夹，再从指定博主列表同步：内容实体只有一份，来源关系保留多份，有效转写和画面提取复用。只增加关系不能再收一次提取费用；内容变更或用户明确重提取则另立处理版本。

作品发布时间、用户真实操作时间、首次同步发现时间必须分开。平台没有提供点赞时间时，可以回答“本次新发现的喜欢”，不能回答“用户今天刚点赞”。首次导入历史喜欢不能伪装成近期兴趣变化。

关系未出现在局部页面中，只能记为未观察到；登录失效、分页截断和范围缩小不构成取消喜欢证据。来源明确取消或完整检查支持状态变化时才更新关系状态，仍不自动删除已保存内容。首版不建设无限事件历史，只保存满足追溯需要的有限关系状态与检查记录。

### 5.3 偏好分析的交付边界

搜索/列表结果可按来源类型、收藏夹、博主和时间依据过滤。宿主 AI 结合命中资料按需总结兴趣，必须说明基于喜欢、收藏还是批量博主作品，指出时间与覆盖限制。内置内容总结只总结作品内容，不顺便写用户画像；用户纠正/排除的资料不再作为偏好证据。

不从这些行为推断敏感身份、心理健康或其他无充分依据的个人属性。用户自己的备注与 AI 推断分开保存；首版默认不持久化自动偏好结论。

## 6. 文件、索引、版本与恢复

### 6.1 新库与旧库

沿用现有工作区约定：`context-workspace.json` 指向资料目录；素材 Markdown 与附件放在 `content-vault/00_素材收件箱`、`content-vault/80_附件`；新增 `.context` 保存条目、来源关系、任务、索引及有限日志。旧库通过布局适配读取，不重命名整库。

普通用户可在编辑器中看 Markdown，Obsidian 可选。用户备注独立保留；程序覆盖派生结果前检查版本，不覆盖用户编辑。手工修改后重建相关索引，并将依赖旧内容的摘要标为过期。

### 6.2 单写与提交

- 一个服务拥有库写锁；CLI/MCP 写请求交同一服务。第二个写服务拒绝启动，不能仅靠进程内布尔变量。
- 先在同一文件系统的暂存区写完整产物并校验，最后原子发布清单作为提交点；读者只读取已提交版本。中断后根据清单恢复，孤立暂存物不算完成。
- 同步页的内容及关系保存成功后再提交游标；失败恢复重读该页，依靠作品/关系/任务幂等去重。
- 外置盘掉线时暂停；检查库 ID 与挂载身份，不在同名空挂载路径创建新库。磁盘空间不足在下载或付费前阻塞。
- 首版支持本机磁盘与已验证外置盘；不支持多机器同时写同一 NAS/云同步目录。若文件事务复杂度失控，单独提出嵌入式数据库比较，由用户确认后调整。

### 6.3 索引与读取

首版关键词/中文词段/常用别名检索，优先准确工具名、代码和提示词；宿主 AI 可有限改写查询。语义向量增强不作为首发依赖，不自动调用 embedding 服务。

索引在启动/内容提交时更新，查询不重新跑全量提取。冷启动报告建索引进度；未覆盖全库时返回 `coverage.partial`。持久缓存可删除重建，缓存命中也要检查当前授权、排除状态及内容版本。

无结果区分“确实未命中”“资料已入库但尚未提取”“索引尚未覆盖”，带下一步说明；不能让 AI 误以为用户根本没有相关收藏。

旧 `m1:` 引用通过兼容映射解析；新引用为稳定条目/产物引用。分页绑定内容版本，版本变化返回重新读取提示；不让两版正文拼成一份证据。

### 6.4 排除、删除、清理与备份

- 排除立即影响搜索、直接读取和偏好证据；磁盘可保留，索引必须同步移除可见内容。
- 用户删除先预览影响，优先移入本库回收区；恢复后重新索引。永久删除单独确认，不因取消喜欢而删除。
- 清理原视频仅在用户已开启策略、所需提取完整且无待处理任务时执行；低质量、部分完成、被占用或来源不明的媒体不自动清理。原文、关键帧、转写及来源清单保留；该策略不扩展为自动删除图文作品的原图。
- 完整备份包含正文、所选媒体、条目关系和任务清单，清楚列出被排除的大媒体；不包含平台登录态和模型密钥。关闭自动任务后做一致快照，保留校验清单。
- 恢复到新路径后检查库 ID、引用、文件哈希、缺失附件和索引重建；默认不自动恢复同步/付费运行，凭据另行配置。导出单份资料包与整库备份不是同一功能。

### 6.5 一份资料实际保存什么

下例是新库的文件职责示意，目录和清单 Schema 在 G2 原型通过后冻结；占位 ID 不对应真实用户资料。旧库经布局适配连接，不按示意批量改名。

```text
资料库根目录/
  context-workspace.json                     库 ID、布局与版本，不含秘密
  content-vault/
    00_素材收件箱/抖音/标题--短ID.md          可读入口，关联来源和各类产物
    80_附件/抖音/<条目ID>/
      原始媒体/                             视频或按顺序保存的图文原图
      <处理版本>/
        音频转写.md
        画面文字.md
        内容总结.md
        可读内容.md
        选帧记录.json
        关键帧/
      用户备注.md                           与机器产物独立，重跑不覆盖
  .context/
    条目/                                   有版本的身份、来源关系与产物清单
    任务/                                   检查点、尝试、调用意图和用量
    提交/                                   提交清单与当前有效版本指针
    索引/                                   可重建派生数据
    暂存/                                   未提交文件，读者不可见
    回收区/                                 用户删除后的可恢复内容
```

产物清单是版本与状态的依据，Markdown 是实际可阅读的内容。两者在同一提交中关联，不能出现清单说“完成”但文件尚未写完。提交指针切换前校验全部引用；指针切换后读者只认该版本，页面与索引可从清单修复。状态恢复不依赖某个 Markdown 文件恰好存在。

画面文字逐页记录帧 ID、视频时间或图文序号、对应图片及疑似字词；音频分段记录起止范围和是否有可靠逐字时间戳。总结的关键事实回指这些证据 ID，模板归纳单列，不能排版成原作者逐字提示词。用户即使不用 AI，也能从“可读内容”打开原图核对。

导出/备份恢复需拒绝库外路径、归档中的链接、重复冲突路径和超出大小/文件数限制的包，先到空的隔离目录验证清单及哈希。失败不覆盖当前库，未确认的新格式不能由旧程序直接写入。

## 7. 同步、媒体处理与费用流程

### 7.1 同步流程

校验连接与范围 → 获取一页 → 校验作品/来源语义 → 内容及关系去重 → 保存元数据和附件任务 → 提交本页检查点 → 判断范围上限/下一页 → 形成覆盖报告。

必须处理重复页、置顶作品、游标不前进、顺序变化和暂不可访问作品。不能仅遇到一条已存在内容就停止增量；设置有界重叠检查。无法证明列表按时间稳定排序时，不做基于发布时间的提前截断。

来源列表失败与作品失败分开：部分作品失效时其余已保存内容不回滚，任务可为部分完成；账号失效或平台验证则停止后续请求。每个来源有限重试、退避和停止条件，不尝试绕过访问控制。

### 7.2 视频与图文处理

1. **预检**：文件校验、格式/时长/尺寸、磁盘空间、模型能力、预算与已存在有效产物。
2. **音频**：本地抽音轨，按已验证模型的文件/时长限制分段，再调用云端音频模型。分段保留起止范围；重叠内容合并有来源，不编造逐字时间戳。无音轨标不适用。
3. **候选帧**：程序检测画面变化，本地 OCR 提供文字/框/置信度辅助选页；记录选中原因、时间、采样覆盖和降级情况。
4. **画面提取**：把选中原图交云端视觉模型，保留提示词、代码、参数、数字、工具名和不确定字词。图文作品按原图顺序逐张处理，不走抽帧和音频分支。
5. **总结**：基于标题、原文、已提取音频和画面形成一次总结，输出概要、步骤、工具/参数、可复用提示词及缺口；不存在的字段留空，区分引用与归纳。
6. **提交**：原文、转写、画面文字、总结和可读入口分别保存，更新产物清单与索引。部分证据失败时可保留其余内容，但摘要及详情必须显示缺口，不标完整成功。

音频和画面可并行，但预算和并发统一控制；总结等待本轮证据阶段结束。文字修改或摘要重做不重新调用音频/视觉。默认无整视频模型调用，无额外逐图 AI 复核；编排检查覆盖空结果、截断、缺页、版本错配与格式异常。

音频及总结还需单独质量验收：固定样例具有人工核对的转写与关键事实清单，包含中英工具名、数字、多人讲话、音乐背景和较长停顿。记录转写遗漏/错字、关键事实是否准确或标疑，以及摘要是否能回指证据。HTTP 成功只证明接口响应，不能代替质量验收；任意用户自配模型的质量不作统一保证。不支持的输入或明显异常要提示，不能靠摘要补写缺失原文。

### 7.3 OCR 与选帧验证

以 RapidOCR + ONNX Runtime CPU 为候选，Mac 现有 Apple Vision 作为对照；统一输出框、文字、置信度、错误和版本，不直接复用不同引擎的置信度阈值。

准备至少 10 段原创/获授权视频，人工标注不少于 50 个关键页，覆盖：短暂提示词、中英混排、小字代码、滚动长文、字幕频繁变化、静态讲解、动画转场、低对比度和竖屏。必须包含一段类似历史“20 秒后提示词”的回归样例。

同时记录候选采样遗漏与 OCR 选页遗漏。当前每秒采样仅作对照基线；必要时在变化附近加密采样，不能承诺换 OCR 就解决所有闪帧遗漏。字幕区域持续变化不得造成无界云请求；局部变化规则需用标注样例验证，不能为了省帧把正文区域误当字幕抑制。

验收目标：标注为关键的提示词/代码页在固定测试集全部被选中，整体关键页召回不少于 95%；另报告重复帧比例、云端帧请求数量、耗时和峰值内存。该目标仅限测试集，不宣传任意视频无遗漏。超帧数上限须明确阻塞；OCR 不可用不得静默当空文字成功。

### 7.4 云模型配置与上传

每个配置保存地址、协议类型、模型 ID、角色、能力限制与凭据引用。首版验证兼容聊天接口的图像/文本及至少一种音频接口；聊天中的音频输入和专用转写接口分适配，不能假设所有兼容端点均支持。

能力测试用小型原创样例，不把第一份私人视频当隐式测试。大音频先分段；不得为了模型下载方便把私人媒体自动上传公共网盘或开放公网文件目录。确需临时对象存储的供应商留作显式扩展，否则返回不支持该输入方式。

模型或提示词切换产生新处理策略版本，默认只影响后续任务；当前任务固定策略，历史产物不被自动全库重算。失败不暗中切换其他供应商或账户。

### 7.5 预算、缓存与真实用量

- 任务提交展示条数、音频时长、帧数上限、模型角色；有可靠价格配置才给金额估算，缺价格显示未知。
- 硬限制采用条数、时长、帧数、调用次数、并发和输出上限；金额控制是基于供应商可得信息的预留/估算，不保证跨供应商精确封顶。
- 每阶段发请求前持久化调用意图及预算预占，结束后记用量；进程崩溃后“可能已发出”的请求标为结果待确认，不自动重复。
- 记录提供者、实际模型、请求次数、输入/输出 token、缓存用量（上游确实返回时）、音频/图片计量、请求标识和耗时。缺字段保持未知，不能将未上报缓存视为零命中。
- 自有内容缓存依据输入哈希、阶段、模型与提示词版本命中；不把供应商缓存折扣当作自有阶段复用。多来源只更新关系时不新增媒体调用。
- 手动运行同样受预算约束；更改额度不自动重试所有失败历史。未完成的预算预占恢复时需核对，不凭时间过去就释放并重发。

### 7.6 可直接拆成代码与测试的阶段契约

| 阶段 | 输入与前置条件 | 持久输出 / 失败时保留 |
| --- | --- | --- |
| 解析与保存 | 已授权范围或支持的链接，来源覆盖与内容身份明确 | 原文、条目及关系；媒体不可访问也保留元数据，并标明原因 |
| 媒体准备 | 已保存的附件描述、下载权限、可用磁盘与大小限制 | 原始文件哈希、媒体探测结果、音轨和候选帧；本地失败不发模型请求 |
| 音频提取 | 音轨、分段范围、已验证音频角色、阶段预算 | 每段转写、范围和用量；已完成段复用，其他段失败不抹掉成功结果 |
| 画面提取 | 选帧清单或有序原图、视觉角色、剩余额度 | 每页提取、证据 ID、图片关联与用量；部分缺页明确列出 |
| 汇总 | 本轮确定版本的原文、已结束的音频/画面结果与缺口 | 一份内容总结；缺口继承，摘要重试不重做音频和画面 |
| 提交与索引 | 完整校验的暂存产物、预期旧版本、库写锁 | 原子提交的新版本与索引更新通知；冲突/空间不足保留可恢复暂存 |

每个处理器只接收阶段输入与显式依赖，不自行读取全局 `.env`、启动同步或决定扩大预算。阶段返回成功、部分完成、不适用、失败或结果不明，流程模块统一决定下一步。下载、OCR 等未发云请求的可恢复故障可有界重试；云请求按第 7.5 节记录，不能套用同一重试装饰器。

自动提取依据启用时的规则版本与观察边界，为符合条件的新条目创建任务。已有内容仅新增来源关系时不重提取；开启自动时已有的历史待办保持待处理。暂停期间已排队而尚未发出的自动任务暂停，用户手动任务另行标记；恢复需展示待处理数量，不能把积压视为隐式无限授权。任务按持久策略执行，不读取正在变化的全局默认值。

全程仅有三个模型角色：音频负责转写，视觉负责原图文字与必要画面描述，文本负责一次内容总结。登录、下载、变化判断、分页、去重、任务状态、文件提交及普通搜索由程序完成；宿主 AI 在检索之后负责用户当前问题的分析与回答。这两个总结/回答用途分开记录，不在每次搜索中再调用库内问答模型。

## 8. 任务、接口与权限契约

### 8.1 状态与幂等

任务状态：`queued → running → succeeded / partial / failed / cancelled`；需要用户输入为 `blocked`，解决后可重新排队。产物状态独立为 `missing / ready / failed / stale / not_applicable`；准确度/覆盖另记。

每阶段记录输入版本、状态、检查点、尝试次数、产物、用量和可恢复错误。提交成功后返回任务 ID，不等待整条视频完成；UI 轮询/事件展示进展，底层持久化是必要条件。不能用 HTTP 框架的一次后台回调假装可恢复任务系统。

有副作用请求要求幂等键：相同身份/权限范围内同键同参数返回原任务，不同参数同键返回冲突。相同条目不同来源并发到达也合并有效处理；取消与重试保留原尝试记录，不抹掉费用。

### 8.2 业务接口表（设计，尚未实现）

HTTP 路径建议使用 `/v1`；MCP/CLI 调相同应用服务。下表路径是拟定契约，不是当前可调用的地址。

| 用例 | 建议 HTTP | AI 暴露 | 权限/输出 |
| --- | --- | --- | --- |
| 搜索 | `POST /v1/collections/search` | `search_collections` | 读库；少量命中、引用、证据类型、来源关系和覆盖 |
| 读取 | `POST /v1/collections/read` | `read_collection` | 读库；引用、产物、长度、分页/版本，禁止任意路径 |
| 资料状态 | `GET /v1/collections/{ref}/status` | `collection_status` | 读库；各产物状态、缺口和过期信息，不触发处理 |
| 单链接入库 | `POST /v1/collections` | 可选 `add_collection` | `collections:add`；URL、幂等键，返回任务 ID/已有条目 |
| 任务查询 | `GET /v1/jobs/{id}` | 写入包的 `get_job` | 仅本凭据有权看到的任务；不泄露其他任务输入 |
| 同步 | `POST /v1/sync-jobs` | 默认不暴露 | 管理权限；已配置 scope ID、数量/范围、幂等键 |
| 手动提取 | `POST /v1/processing-jobs` | 默认不暴露 | 管理权限；条目引用、阶段、费用确认、幂等键 |
| 取消/重试 | `POST /v1/jobs/{id}/cancel`、`/retry` | 默认不暴露 | 管理权限；重试返回新尝试，结果不明时要求确认 |
| 来源与配置 | `/v1/settings`、`/v1/sources` 下的受控操作 | 不暴露 | 管理会话；只接受类型化字段，密钥永不回显 |
| 排除/删除/导出/备份 | 独立受控管理用例 | 不暴露 | 预览范围再确认；禁止接收任意 shell 或远程任意路径 |

`collections:add` 本身不授予付费权。允许“AI 提交后按自动策略提取”时，需要用户给该接入单独启用受预算约束的自动提取权限；否则仅保存为待处理。管理页的个人自动开关不能被低权限 AI 凭据当作通用费用授权。

首版默认三个只读工具；可选写入包额外提供添加和对应任务查询，不把内部所有管理 API 注册成几十个工具。读库的正常检索不触发模型、同步、重试或其他任务。

### 8.3 输入输出与错误

- 公共结果包含 `ok`、`data`、`error` 和 `meta`；`meta` 至少含契约版本、请求标识、内容版本/覆盖适用项。具体 JSON Schema 在获准开发后的契约阶段冻结。
- 错误包含稳定代码、用户可读原因、是否可重试、下一步以及是否可能已产生上游费用；MCP 业务错误映射为工具错误，不能把失败包装成成功。
- 搜索默认 3 条、建议上限 20；读取延续默认 4,000 字符并设置字节保护，上限统一。列表分页游标不可由客户端拼路径，过滤/权限/版本变化时旧游标失效。
- 保留当前 `material_ref`、`artifact`、`offset`、`max_chars`、`version` 的兼容层；新版本分页方式不直接破坏旧 Agent 配置。
- 来源过滤区分喜欢/收藏/收藏夹/博主/链接；时间过滤必须包含时间依据，未知真实操作时间的结果不能混入“最近点赞”的确定列表。
- 典型错误：`login_required`、`scope_unavailable`、`source_partial`、`artifact_missing`、`version_changed`、`budget_required`、`upstream_outcome_unknown`、`storage_unavailable`、`permission_denied`、`idempotency_conflict`。

### 8.4 接口示例与 AI 的正常调用顺序

以下都是拟定契约示例，字段在 G2 冻结，没有创建这些 HTTP 接口。权限和库范围由服务端凭据决定，请求不得附带任意本地库路径。

搜索请求示例：

```json
{
  "query": "UI 多页面 提示词",
  "limit": 3,
  "filters": {"source_kinds": ["liked", "saved", "collection"]}
}
```

单链接请求示例（请求头另传产品访问凭据和 `Idempotency-Key`，不传模型 Key）：

```json
{
  "url": "https://www.douyin.com/video/<作品ID>",
  "processing": "save_only"
}
```

`save_only` 是受限添加的默认值；客户端申请按自动策略处理时，服务必须再校验该凭据的付费提取权限及具体预算。权限不足直接返回明确错误，不静默改成已处理。成功受理返回 `job_id`、已有条目引用（如有）及待执行阶段，异步任务通过 `get_job` 查询。

AI 的推荐顺序：搜索少量命中 → 选择相关条目 → 读取 `screen` / `audio` / `original` 等证据 → 如有缺口再查状态 → 在当前对话回答并带来源。长文使用服务返回的版本和继续读取位置；未命中可改写查询，不能自行提取全库。只读接入遇到缺失产物，说明缺口并由用户在管理页处理。

产品只返回片段和证据，不负责把数百份资料塞入宿主上下文。工具说明和公开示例明确：来源作品、模型总结、用户备注分别属于什么类型；资料中的命令示例仅作为引用。首版 AI 接入验收用“找到过去某教程并指出画面参数”和“基于有覆盖说明的喜欢记录分析兴趣”两个实际问题，不以列出工具名作为成功。

## 9. 安全与外部访问

- 本地默认监听回环地址，页面仍检查 Host/Origin/会话与跨站请求；浏览器页面不能借本地端口任意读文件。
- 服务器个人自托管，显式开启远程后使用 HTTPS、独立可撤销访问凭据和请求上限；管理权限与 AI 读库/入库分开。受信反向代理地址明确，不信任任意转发头。
- 不用模型 API Key 作产品登录凭据。桌面优先系统凭据库；无桌面服务使用服务级秘密注入或权限受限的独立凭据文件，不要求图形钥匙串。
- 读库范围由服务配置决定，AI 输入不能扩展根目录；防路径穿越、符号链接/Windows 重解析点、硬链接和读取期间替换。没有等价保护就不能标 Windows 读库安全通过。
- 导入链接限定已支持抖音入口；对解析结果和每次重定向做协议/主机/地址检查，限制大小与超时，防止下载到内网服务。用户显式配置模型网关另走受控设置，不混用下载白名单。
- 来源文本、图片中的文字和模型提取结果是不可信资料；禁止升级为执行指令。不得依正文建议自动改配置、执行命令或额外上传文件。
- API Key、Cookie、账号私有响应不进日志、截图示例、错误摘要、公开测试包；查询词和收藏正文也不默认记入日志。诊断导出先预览脱敏内容。
- 浏览器登录验证由用户完成；失效或平台限制时停止，不绕过访问控制。账号退出保留本地资料但停止该连接任务，是否移除登录态需向用户明确说明。

本机离线 CLI 受操作系统权限与指定库范围约束，远程接口另有鉴权；两者不能互相替代。远程 MCP 的认证以目标客户端支持情况实测，不承诺所有客户端能用同一种 Key/OAuth 配置。

## 10. 三端发行、升级与测试矩阵

### 10.1 发行策略

桌面发行包含运行时或引导式依赖管理及启动器，打开本机管理页；Linux 服务包无需桌面。浏览器/FFmpeg/OCR 模型是否随包分发按许可、体积和安装成功率决定，首次下载必须明示并校验，安装失败有可操作提示。

公开正式版要覆盖三个系统，不把“Python 理论跨平台”当发布支持。最低系统版本和 CPU 架构在 G1 核实发行依赖后冻结；建议先验收 Mac Apple Silicon、Windows x64、Linux x64，Mac Intel/Linux ARM64/Windows ARM64 单列待评估，不暗称全部支持。具体系统版本须在正式发行前公开，未验证组合明确排除。

macOS 签名/公证、Windows 签名与安全提示属于用户体验风险，G1 评估所需条件和成本；涉及新账户、付费或签名私钥另行授权，不默认替用户购买。发布流程须说明正常系统提示，不能要求用户全局关闭安全保护。

### 14.3 对象和身份：现在先定清楚

以下是未来业务契约草案，未写入当前库。

| 对象 | 保存什么 | 和其他对象的关系 |
| --- | --- | --- |
| 收藏资料 `SourceItem` | 外部作者内容、来源、原媒体、提取产物、观察记录。 | 被笔记、选题和草稿引用；保留现有 `i_` 身份与去重规则。 |
| 知识笔记 `Note`（可后置） | 用户提炼的观点、方法、提示词或案例；可以基于多条资料。 | 引用资料或其他笔记；用户自己的判断与原始事实分别可追溯。 |
| 选题 `Topic` | 想解决的问题、受众、角度、判断、参考、优先级。 | 可以引用多条收藏；可产生一份或多份草稿；生成草稿后仍保留选题。 |

通用约定：每类对象有稳定 ID、类型、标题、创建/更新时间、内容版本；标题改名、文件移动和视图切换不改变身份。来源作品和“我的作品”在语义上区分；同一平台作品同步多次仍只存一份。新增对象不改变现有收藏引用。

正文/媒体文件保留实际可读路径；业务关系使用稳定 ID。索引、Markdown 链接和图谱视图都从同一组身份与关系派生，避免每个界面另存一套关系。

### 14.4 关系分三类，分别保存依据

| 类别 | 例子 | 保存与显示原则 |
| --- | --- | --- |
| 来源关系 | 资料 A 属于收藏夹 B；来自博主 C。 | 沿用 `SourceRelation`，记录来源和观察时间。 |
| 明确引用与创作关系 | 选题 T 参考资料 A；草稿 D 引用画面片段 F；作品 W 来自草稿 D。 | 保存起点、终点、关系种类、建立者、建立时间，以及必要的片段/版本；可反向查询“哪里使用过它”。 |
| 推断/推荐关系 | 两条资料提到同一工具；模型认为适合一起研究。 | 单独保存推荐理由、生成方法/模型和时间；与用户确认关系区别显示，可确认、移除或重算。 |

引用证据计划包含 `item_ref + artifact_kind + artifact_version + locator`。`locator` 按实际产物保存文本位置、音频片段或帧 ID；没有精确时间时保持未知。总结所依赖的产物版本已有基础，后续创作引用沿用并扩展该约定。

反向引用由已有引用边派生，无需用户重复维护。共同概念、二度关联等属于可重建的派生结果，先给出“通过哪个引用/标签相关”的解释。语义相似可以以后加入；其输出属于推荐线索。

当前 UI 的来源标签继续对应平台关系。未来“关联内容”使用新的内容关系接口，避免把现有 `relations` 改名后当成知识图谱。

### 14.5 用户路径与分期交付

```text
收藏资料 → 提取与阅读 → 选择参考资料 → 形成选题
                                       ↓
                                   草稿与制作
                                       ↓
                                    我的作品
                                       ↓
                                发布记录与表现
                                       ↓
                              复盘 → 新选题/修改
```

| 批次 | 用户获得什么 | 本期先规划什么 | 日后完成时的可见验收 |
| --- | --- | --- | --- |
| 当前 MVP | 抖音收藏整理、提取、读取与 AI 调用。 | 稳定身份、提取证据、对象与关系边界；后续模块的接口方向。 | 保持 R01～R14 原范围验收；仅“规划完成”不能算后续模块已实现。 |
| MVP 后第一小批 | 轻量选题池与明确引用。 | 从已选收藏创建选题；记录问题、角度、参考、自己的判断；查询引用/被引用。 | 选三条收藏形成一个选题，每条引用能回到来源与当时版本；修改标题不丢关系。 |
| 下一小批 | 创作台与基础作品库。 | 从选题建草稿、保存版本、关联正文与附件；草稿可以交由自己的 AI 撰写。 | 一条选题变成草稿再归入我的作品；旧选题仍在、原收藏仍在、正文版本可回查。 |
| 后续 | 排期、发布登记、复盘。 | 计划/实际发布时间、平台版本、表现快照、复盘引用；自动平台数据接入按能力逐项做。 | 同一作品发布到两个平台，分别记录结果；能解释复盘依据哪次快照。 |
| 增强项 | 概念/语义关联、图谱探索、推荐。 | 先利用已经存在的引用关系，再评估共同概念与语义召回。 | 每条关联解释依据，人工确认和模型建议可区分；图谱与列表结果一致。 |

关系读写的基础随第一小批进入；复杂概念图谱与动效不阻塞选题和创作闭环。独立知识笔记可根据真实需求插入选题前，不强制所有用户先做一遍笔记。

2026-10-05 用户进一步确认：产品整体以创作工作台组织，收藏只是其中一部分。顶部采用“工作台 / 作品库 / 创作台 / 选题池 / 收藏库”；工作台画布保留参考案例的“概念网络 / 方法库 / 作品库 / 选题池 / 创作台”，另加“收藏库”。喜欢、收藏、指定收藏夹、博主作品和单条链接仅作为收藏库内部来源；同步归入收藏库，AI 接入和模型配置归入设置。

独立交互样稿可以先展示未上线模块的结构与定位，必须明确标注“规划中”，不得伪造创作数据、数量或可用编辑功能。此项覆盖此前“未上线功能不出现在导航”的界面安排，不扩大本轮后端开发范围。图谱、列表、详情和日历仍应是同一业务对象的不同视图。收藏到笔记/方法、选题、草稿、作品是可选的引用路径，用户可直接创建选题或草稿，不强制从收藏起步。

### 14.6 底座复用与必要调整

**统一后端继续作为底座。** 复用 `sources` 的采集、`processing` 的提取、`library` 的资料与引用读取、`workflows` 的长任务、`interfaces` 的 CLI/HTTP 入口；同一进程提供能力，不另起独立创作服务部署。

日后在统一包内增加小型创作业务模块，负责选题、草稿、作品及其状态转换。跨内容关系由库层提供共享服务。模块有明确对象后再拆文件，不先为全部远期功能生成空架构。

需要提前处理的三点：

1. **身份和平台适配。** 当前 `item_id/validate_source` 只接受抖音；将来来源适配与通用创作对象分开。现有稳定资料 ID 保持兼容，草稿/作品有独立身份。
2. **处理状态与创作状态。** `queued/running/partial/failed` 表示后台任务；选题待定/已选、草稿修改/待录制/待剪辑、作品待发布/已发布表示业务进度。一次总结失败不能把整篇创作改成失败状态。
3. **结构化存储。** 当前库将条目与任务写入整份 JSON 提交，提交正文上限为 16,000,000 字节；资料变动会重建派生索引。这个数字约束清单，不是媒体容量，也不能换算成确定的作品上限。创作记录、关系边和频繁编辑增多前，需要调整存储实现。

存储规划建议：媒体和 Markdown 继续放文件系统；进入创作模块前，优先评估用嵌入式 SQLite 保存结构化对象、关系、版本引用与任务状态。由一个后端维护，用户无需另装数据库服务器；搜索和图谱索引可重建。此建议待后续小样本读写/恢复验证后实施，本轮不安装或迁移。

采用该方向时，需指定 SQLite 为结构化元数据的权威来源，正文文件为具体版本内容；文件先落盘校验，再提交数据库引用。可读入口与搜索索引属于派生物。外部手改 Markdown 经明确导入/登记成为新版本，不允许文件和数据库各自悄悄改同一字段。迁移保留原 ID、现有 API 行为、产物路径和版本，完成对照后切换一个写入口。

当前的读服务契约有助于保留上层调用，但写库、备份和索引实现仍需要适配；不把这次存储建议说成“已有即插即用数据库层”。图数据库、独立向量服务或新增服务器并非这条路线的前置要求。

### 14.7 AI 和页面怎样共同使用

新增业务由应用层提供相同动作，CLI 与页面调用同一套逻辑。用户自己的 Personal Agent 可完成内容判断与起草；不要求产品再内置一套总控 Agent。

| 计划能力 | 输入 | 输出 | 上线阶段 |
| --- | --- | --- | --- |
| 读关联 / 被引用 | 对象 ID、关系种类、方向 | 对象列表、关系原因、证据版本 | 轻量选题与关系 |
| 创建 / 更新选题 | 问题、角度、参考资料、用户判断、预期版本 | 选题 ID 与版本、参考清单 | 轻量选题与关系 |
| 从选题创建草稿 / 保存正文 | 选题 ID、正文、引用片段、预期版本 | 草稿 ID、新版本、保留的引用 | 创作台 |
| 归档为作品 | 草稿版本、标题、正文/媒体资产 | 我的作品 ID、来源草稿与素材关系 | 基础作品库 |
| 登记发布 / 表现 | 作品版本、平台、实际时间、链接、指标快照 | 发布记录、快照 ID | 发布与复盘 |

这些是计划中的应用能力，不代表现有命令已可执行。现有 `search/read/status` 行为和引用保持兼容。AI 写入用户创作内容时使用对应动作，执行前检查预期版本，防止两个入口互相覆盖；普通读取不隐式生成草稿或再次调用模型。
