## 1. 实际新增什么

运行代码全部在 `backend/src/collection_context/`。同步、转写和工作流的业务实现由本项目重写；旧 `app`、dYm、其他项目 CLI、账户目录及本机 `.env` 都没有进入新运行链路。通用 FFmpeg、Python HTTP、MCP SDK 和 CPU OCR 库保留为正常基础依赖。源码独立不等于外部项目/协议/模型许可审查已经完成。

| 自有模块 | 职责 | 本批边界 |
| --- | --- | --- |
| `infrastructure/ownership.py` | 操作系统独占执行权、路径/挂载身份检查 | Mac 已验证；Windows 尚未适配 |
| `workflows/executor.py` | 固定阶段计划、依赖、检查点、复用、取消与调用上限 | 内部串行执行核心，不是对外同步长请求，也没有后台调度服务 |
| `workflows/jobs.py` | 请求前意图、确认结果与用量一次提交、结果哈希 | 结果不明阻塞；显式核对/重试界面尚未实现 |
| `processing/stages.py` | 自有音频、图像、汇总提示词和直连接线、阅读稿落库 | 用户的三角色云模型；本批响应仅为合成测试服务 |
| `library/store.py` | 多份机器产物作为一批原子可见 | 用户备注保留；手改机器文件先报冲突，不自动覆盖 |

阶段关系：

```text
固定媒体快照 + 模型角色/参数 + 处理策略
    ├─ 音频片段 → 直连音频模型 → 片段文字、范围、用量
    └─ 原图候选 → 直连视觉模型 → 画面文字、证据编号、用量
                      ↓
           自有汇总提示词 → 摘要、引用、缺口
                      ↓
    音频转写 / 画面文字 / 内容总结 / 可读内容
                      ↓
       同一次库提交可见 → 更新派生索引 → 只读查询
```

云请求由用户显式提供的配置与凭据发起，没有新建模型服务，没有调用别的项目作为中转。当前三个只读 AI 工具没有获得启动上述付费流程的权限。

## 2. 避免重复请求的实际规则

1. 提交时固定处理阶段、媒体哈希、逻辑模型地址/名称/协议/参数及策略版本。执行不悄悄改用新的默认模型，密钥不进入任务计划/结果文件。
2. 音频/图像角色先检查能力协议、媒体大小、哈希与图片格式；汇总证据超限在请求意图之前拒绝，不能截断后宣称完整。
3. 请求之前持久保存意图和调用上限；确认响应后，把结果指针、哈希、实际模型、请求标识、用量与完成状态放进同一次库提交。缺失的模型/缓存/用量字段保持未知。
4. 同一拥有者、输入和策略的完整确认结果可跨任务复用，部分/失败结果不自动成为全局缓存。标题/原文单独变化时，可复用未变的音频/图像提取，汇总重新计算。
5. 正在运行时取消，不再派发后续阶段；已发请求的晚到结果/用量仍登记。取消不是上游退款承诺。
6. 网络中断、请求之后进程退出、收到无效输出等结果不明的请求保持阻塞；新建任务也不能绕过同输入未明请求。没有无限重试或自动修复摘要的额外模型请求。
7. 恢复运行任务须持有同一库的操作系统独占锁，并验证身份/任务范围。锁文件残留不代表进程还在，也不能单凭文件时间认定旧执行器已死。

请求结果是版本化 JSON，读取要验证受控路径、哈希与结构；损坏结果不自动重发计费请求。此批337项实现的排他文件写锁尚不能自动恢复；后续新协议已补局部文件系统上的进程死亡恢复，见第6节。遗留旧写锁不自动清除，执行锁测试不能替代写事务和磁盘故障验收。

## 3. 内容完整与流程完成分别报告

- 音频保留片段开始/结束和重叠说明；没有伪造逐字时间戳，重叠部分的精细拼接仍待实现。
- 画面保留真实证据编号、原图哈希和采样网格的名义时间；不是逐帧原始时间戳。
- 汇总提示词要求区分原文提示词与归纳模板，重要事实附证据编号，继承失败/听不清/覆盖缺口。资料中的命令只作引用。
- 本地检查会标记不存在或完全缺失的音频/画面引用；**有引用不代表事实已逐条证实**，没有暗中增加二次 AI 核验。
- 处理阶段执行成功可以与 `coverage.complete=false` 同时出现。读取会显示覆盖未知/不足提醒；选帧、真实 ASR/视觉精度和总结质量另做验收。
- 写产物前核对输入版本和现有机器文件。人工改动会产生冲突；不清用户备注，不把旧文件静默当成准确内容。

## 6. 后续实现：写事务进程死亡恢复

### 输入、输出和失败边界

- 新库初始化保存 `writer_protocol=os_writer_v1`。事务锁为 `.context/写入所有权.lock`，与长任务执行权分开；两者共用自有受控文件/操作系统所有权适配。锁文件仅用于诊断，真正占用由内核排他锁决定，正常释放和进程死亡均不删除该文件。
- 保留 `.context/写锁.json` 为旧版本写入保护标记。旧代码使用排他创建，会被此标记挡住；新代码校验标记，缺失/变化即停止写入，不能让新旧版本各持一套锁并发写库。该保护标记长期存在不代表新写入器正在运行。
- 事务读取当前不可变版本、执行变更、写新版本，并在切换 `CURRENT.json` 前再次核对所有权、工作区身份及旧版本保护。提交前退出只留下不可见孤立版本；提交后退出保留完整已提交版本。后续进程可继续写，不把半成品当成成功，不重复创建同一作品。
- 旧开发库仍可只读访问；写入报 `writer_upgrade_required`，须本机显式执行 `collection-context --workspace <新产品库> upgrade-writer`。先停止旧版本；命令只改变写入协议，不搬移/清除作品、来源关系、任务或产物，不开启自动处理，不请求平台或模型。
- 升级用新内核锁串行化，并通过原排他创建规则取得旧协议保护；已有任何未知旧锁（包括空、损坏、很旧或虚假PID）都拒绝接管。不能据此认定旧进程已死，也不提供盲目删锁命令。
- 升级在保护写入后、配置切换前失败，可重跑命令接续本产品已知保护标记；其他标记不自动修复。已升级的命令幂等；未知未来协议不降级。没有对生产库或先前真实公开样例库执行升级。
