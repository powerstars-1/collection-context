# 页面刷新频率与共享进度

## 问题与范围

同步页原先有三个 5 秒循环；全局任务循环每 5 秒翻全部任务历史。现场 28 条任务、两页，空闲单页约 60 请求/分钟。任务详情还额外每 2 秒查询处理计划、每 5 秒查询正文状态。正常操作会和按身份统计的 120 请求/分钟上限冲突。

本轮修改刷新行为，不提高限流、不修改登录身份或模型配置，不启动真实同步或新的云模型提取。

## 调整后的规则

| 场景 | 刷新规则 |
| --- | --- |
| 初次打开页面 | 读取该页面所需数据一次 |
| 空闲 | 共用一个轻量 `/v1/management/activity` 检查，每 30 秒一次 |
| 有排队/运行任务或连接操作 | 共用检查每 5 秒一次 |
| 同步来源 | 首次加载、手动刷新、同步任务变化时刷新；不单独循环 |
| 抖音连接状态 | 首次加载、连接操作完成时刷新；不单独循环 |
| 登录/获取收藏夹操作 | 仅操作活跃时每 3 秒读取连接进度，结束即停止 |
| 内容任务列表 | 初次进入/手动刷新读取历史；轻量进度合并到现有行，任务新增或整体状态变化时重新读取结果 |
| 内容任务详情 | 首次读取处理计划和正文状态；仅当前任务活跃时每 3 秒更新处理计划，结束刷新一次正文 |
| 单条链接准备、模型连接检测 | 仅该任务活跃时每 3 秒刷新，结束即停止 |
| 提交、取消、重试 | 成功后立即通知共享检查，短暂合并连续通知，不等待空闲周期 |
| 页面隐藏 | 停止轮询；恢复可见时复用最新共享数据或重新检查 |
| 请求失败/限流 | 轮询退避 60 秒；不自动重复写操作或模型调用 |

`activity` 不加载音频/关键帧清单，不访问供应商，不翻页。返回最近 20 条任务与最多 40 条活跃任务的进度、全部活跃任务数量、库/来源变化指纹及 worker 状态；不作为完整历史接口。任务页依然可以查看全部既有记录。

## 标签页协作

同一个客户端的多个组件共用一个内存监视器。同源标签页通过 Web Locks 串行检查和 BroadcastChannel 共享临时进度快照，不把凭据或内容写入 localStorage。浏览器不支持该组合时降级为每个可见标签页各一个低频检查，隐藏页面仍停查。

跨标签页共享只覆盖公共进度检查，不宣称所有用户点击、历史加载和详情读取都只有一份。空闲稳定时约 2 个后台请求/分钟；运行时公共检查约 12 个/分钟，用户打开当前详情等会按表增加必要请求。

## 验证

- 新增模拟时钟测试：空闲、运行转空闲、隐藏/恢复、失败退避、合并正在执行的检查、过期进度不覆盖新结果、两个可见标签页共享、页面不再循环翻历史。
- 新增后端测试：activity 不读取媒体准备详情、不调用云端、读取不修改库、排队与结束信号、拒绝未知参数、沿用页面管理权限。
- 前端回归 165 项通过；相关后端 60 项通过。
- 已部署到本机 8790，浏览器确认收藏页、同步来源页、任务列表与已完成任务详情能正常显示。
- 使用同一共享监视器对真实本机接口连续观测 62 秒：第 0、30、60 秒各请求一次，合计 3 次（含初次加载）；错误 0，云模型请求 0。此项是监视器接真实接口的测试，不把它称作完整浏览器网络抓包。
- 运行状态切换使用隔离合成任务和模拟时钟验证，没有为验证刷新而触发用户的真实计费提取。
